# Plan: Визуальная регрессия без хранения снимков в git

**PRD:** [prd-visual-regression-without-baselines.md](prd-visual-regression-without-baselines.md)
**Дата:** 2026-08-31
**Решения:** ADR-230 (три слоя, пиксели против `merge-base`), ADR-231 (витрина
статикой, шарды)

## Фазы реализации

### Фаза 1: Пиксели без хранения

**Цель:** Сквозной минимум: ни одного PNG-эталона в git, эталон — кадры
`merge-base`, снятые в той же работе; ручное задание пересчёта снято. Именно
эта фаза убирает вес репозитория и класс ошибок ADR-216.
**Затрагивает:** инфраструктура / тесты

**Задачи:**

- [ ] Витрина под снимки собирается статикой (`storybook build`) и раздаётся
      образом `caddy` в обеих работах; кадры совпадают с прежними эталонами из
      git — равенство отрисовки доказано до их удаления (ADR-231)
- [ ] Раннер берёт каталог кадров из переменной окружения, истории без
      базового кадра снимает без сравнения и пишет машинный итог прогона:
      сравнено, разошлось, новых, отказов
- [ ] Работа снимает кадры `merge-base` тем же контейнером и раннером, кеширует
      кадры `main` по SHA и версии отрисовщика, при промахе кеша снимает базу
      сама
- [ ] Сводка расхождений в `$GITHUB_STEP_SUMMARY`, картинки разницы артефактом;
      шлюз ярлыком `vr:accepted`, работа слушает `labeled` / `unlabeled`; отказ
      сценария и падение раннера красят всегда
- [ ] Эталоны уходят из репозитория: PNG удалены, `*-snapshots` в `.gitignore`,
      `vr-baselines.yml` снят, CLAUDE.md / ROADMAP / HANDOFF и комментарии
      раннера описывают новый порядок; закрывает #441

**Проверка:** PR без визуальных правок зелёный без единого PNG в git; PR с
нарочным сдвигом в 1px красный с именем истории в сводке; с ярлыком — зелёный;
новая история не красит; отказ сценария красит и с ярлыком; в журнале работы на
втором PR виден `cache hit`.

**Когда готова:** В репозитории нет PNG-эталонов; `vr` и `vr-panel` зелёные на
`main` и на PR; задания пересчёта нет; критерии PRD 1–7 отмечены.

### Фаза 2: Время ожидания — шарды

**Цель:** Критический путь снимков не длиннее пяти минут при попадании в кеш;
имена обязательных проверок не меняются.
**Затрагивает:** инфраструктура / тесты

**Задачи:**

- [ ] Раннер берёт долю списка историй из `VR_SHARD=k/n`; доли не пересекаются
      и вместе дают весь список — покрыто тестом на разбиение
- [ ] Обе работы идут матрицей шардов; `vr` и `vr-panel` — сводные вердикты над
      шардами, красные при любом красном шарде и при неотработавшем шлюзе
- [ ] Кеш базовых кадров разбит по шардам, ключ включает число шардов; сводка
      собирается из итогов всех шардов
- [ ] Замер до/после (образ, сборка витрины, кадры, критический путь) записан
      в ADR-231 и в описание PR

**Когда готова:** Критический путь `vr` и `vr-panel` при `cache hit` ≤ 5 минут;
числа в ADR-231; защита `main` не переписывалась.

### Фаза 3: Инварианты без эталона

**Цель:** Регрессии раскладки, которые в проекте ловили измерением руками,
ловятся машиной на всех 734 историях — включая `Админка/`, недоступные
пикселям.
**Затрагивает:** тесты / frontend

**Задачи:**

- [ ] Измеритель в странице: переполнение документа по горизонтали, размер
      интерактивных целей (24×24; 44×44 в сенсорных раскладках — ADR-183), фон
      документа равен токену темы и `data-theme` запрошенной, обрезанный текст
      без многоточия, перекрытие цели по `elementFromPoint`, загруженность
      шрифтов (`document.fonts`) и изображений
- [ ] Спек инвариантов на всех историях: публичные разделы на своих ширинах,
      панель и `Админка/` — на своих, обе темы; своя работа пайплайна с
      сторожем «шлюз не отработал»
- [ ] Истории-фикстуры с нарочными нарушениями, скрытые из боковой панели
      тегом: каждое правило доказывает, что падает
- [ ] Разбор существующих нарушений: починить или допустить параметром истории
      с причиной; список допущений виден в сводке работы
- [ ] Документация: CLAUDE.md «Как проверяется сделанное» и раздел тестов
      называют инварианты; DESIGN_BRIEF ссылается на них у тап-зон

**Когда готова:** Работа зелёная на `main`; каждое правило красное на своей
фикстуре; допущения — только параметром с причиной.

### Фаза 4: Измерения текстом

**Цель:** Изменение внешнего вида видно в диффе PR текстом — то, ради чего
PNG лежали в git, — но дельтой и без веса.
**Затрагивает:** тесты / инфраструктура

**Задачи:**

- [ ] Стабильные имена классов CSS Modules (`[name]__[local]`) в сборке витрины
      под снимки — включаются переменной, боевую сборку не задевают
- [ ] Сериализатор: записываемые узлы (модульный класс, роль, текстовый лист,
      `img`/`svg`, псевдоэлементы с `content`), координаты относительно
      записанного предка, белый список вычисленных свойств, текст с числом
      строк, шрифты по `document.fonts`, документ; один файл на историю —
      геометрия по ширинам, палитра по темам; покрыт тестами на устойчивость к
      лишней обёртке и к округлению
- [ ] Компаратор с допусками (1px геометрия, точные цвета и шрифты) и текстовый
      отчёт в сводке работы; тесты на ложные срабатывания из PRD
- [ ] Файлы измерений в git; обновление — из артефакта работы одной командой
      либо локально; локальный пересчёт на macOS сходится с CI в пределах
      допуска — проверено на трёх историях
- [ ] Документация формата и порядка обновления: CLAUDE.md, HANDOFF, ADR о
      формате

**Когда готова:** Правка радиуса карточки даёт дифф ровно в задетых историях и
ровно по этому свойству; лишняя обёртка `<div>` не меняет ни строки; файлы в
git, PNG — нет.

### Фаза 5: Диагностика покрытия и устойчивость состояний

**Цель:** Пиксельный слой перестаёт снимать одно и то же под разными именами, а
проверки устойчивости раскладки, которые делали руками, живут в историях.
**Затрагивает:** тесты

**Задачи:**

- [ ] Отчёт о побайтно одинаковых кадрах разных историй в сводке работы;
      найденные пары разобраны — тегом `vr-<ширина>` либо правкой истории
- [ ] Параметр истории «контрольный элемент стоит на месте во всех
      состояниях»: раннер меряет рамку элемента по состояниям и красит при
      разбросе (случай ADR-212)
- [ ] Граф импортов (#444) применён к пиксельному слою: обе стороны снимают
      только задетые истории; правка токенов и глобальных стилей снимает всё

**Когда готова:** Пар «разные состояния — одинаковый кадр» нет либо каждая
разобрана; #444 закрыт; критерии PRD 11–12 отмечены.
