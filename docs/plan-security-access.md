# Plan: Доработки после аудита — безопасность и доступ

**PRD:** [prd-security-access.md](prd-security-access.md)
**Дата:** 2026-08-29

## Фазы реализации

### Фаза 1: Монтажник видит только своё, вход не уводит наружу

**Цель:** Закрыть три дефекта доступа, которые работают прямо сейчас на
живом стенде: чужие персональные данные в календаре монтажника, открытый
редирект после входа и незащищённые вход с выходом. Минимальный рабочий
путь: правки серверные, экранов не трогают.
**Затрагивает:** backend

**Задачи:**

- [ ] Передать `Viewer` в `listRange` и `listCreatedBetween` и фильтровать
      дела и заявки календаря по роли ([BUGS §2833](BUGS.md), P1)
- [ ] Разрешать возврат после входа только на внутренний адрес — с учётом
      обратного слэша ([BUGS §2854](BUGS.md), P1)
- [ ] Проверять кросс-сайтовость в `POST /api/auth/login` и `/api/auth/logout`
- [ ] Тесты: монтажник не получает ни одной чужой записи и заявки; три вида
      подставного `next` ведут на `/admin`; вход и выход с чужим `Origin`
      отклонены

**Когда готова:** Ответ API монтажнику не содержит чужих данных, тесты на
редирект и кросс-сайтовость зелёные.

### Фаза 2: Прод разворачивается, секреты не утекают

**Цель:** Первый деплой заканчивается работающим входом в панель, а пароль
базы не лежит в метаданных образа и в открытом порту дев-стенда.
**Затрагивает:** backend / инфраструктура

**Задачи:**

- [ ] Провести `$` в значениях `.env.prod` через compose без потерь — хеш
      Argon2id и пароль SMTP доезжают целиком ([BUGS §2908](BUGS.md), P1)
- [ ] Убрать боевую строку подключения из конфигурации образов `build` и
      `worker` ([BUGS §2971](BUGS.md))
- [ ] Публиковать порты дев-состава только на `127.0.0.1` и убрать
      `admin`/`admin` из сценариев ([BUGS §2928](BUGS.md), P1; нужен ADR)
- [ ] Проверка: локальный прогон полного `docker-compose.prod.yml` со входом в
      панель, `docker inspect` обоих образов, `compose config` дев-состава

**Когда готова:** Вход в панель работает на локальном прогоне прод-компоуза;
в метаданных образов пароля нет; дев-стенд не слушает сеть.

### Фаза 3: Данные клиентов и предохранители

**Цель:** Персональные данные клиентов закрыты сессией, а разрушительные
операции не срабатывают там, где их не ждут.
**Затрагивает:** backend / database

**Задачи:**

- [ ] Проверять в `seed:demo` строку подключения, а не `NODE_ENV` и
      `SITE_URL` ([BUGS §3596](BUGS.md), P1)
- [ ] Закрыть фото объекта клиента сессией, оставив публичными изображения
      каталога и статей ([BUGS §3000](BUGS.md))
- [ ] Ограничить число строк в списании в наряд ([BUGS §3704](BUGS.md))
- [ ] Закрыть пачку серверных мелочей: принадлежность заметки сотруднику,
      служебные поля Prisma в `/api/prices` и остальные пункты
      ([BUGS §3468](BUGS.md))
- [ ] Тесты: отказ демо-сида на чужой базе; фото клиента без сессии — 401, а
      обложка статьи — 200; списание сверх предела — 400

**Когда готова:** Демо-сид отказывается работать на не-дев-базе, фото
объектов закрыты, предел строк списания покрыт тестом.
