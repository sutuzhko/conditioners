# Plan: Рабочий процесс по GitHub Flow — worktree на сессию со своим стендом

**PRD:** [prd-github-flow-worktree.md](prd-github-flow-worktree.md)
**Дата:** 2026-08-29

## Фазы реализации

### Фаза 1: Второй стенд поднимается рядом с основным

**Цель:** Сквозной минимум: два дев-стенда живут одновременно и не дерутся за
порты. Пока этого нет, ветки в worktree бессмысленны — проверять код будет
нечем.
**Затрагивает:** инфраструктура

**Задачи:**

- [ ] Параметризовать имя compose-проекта: сейчас `name: conditioner-dev`
      зашито, и второй стенд переиспользует контейнеры первого
- [ ] Вынести порты в смещение: 80, 443, 3000, 6006 и 5432 зашиты в
      `docker-compose.dev.yml` и заняты основным стендом
- [ ] Наполнять стенд worktree только демо-данными: `migrate deploy` →
      `seed` → `seed:demo`, без копирования дев-базы с заявками владельца
- [ ] Проверка: два стенда подняты разом, оба отвечают, ни один порт не занят
      дважды; в базе второго нет настоящих заявок — проверено запросом

**Когда готова:** На машине одновременно работают основной стенд и второй,
наполненный демо-данными; порты не пересекаются.

### Фаза 2: Worktree заводится и сносится одной командой

**Цель:** Сессия получает свой каталог, ветку и стенд без обряда из десяти
команд — и так же их отдаёт.
**Затрагивает:** инфраструктура

**Задачи:**

- [ ] Команда заведения: worktree от свежего `main`, ветка с описательным
      именем, поднятый стенд
- [ ] Команда сноса: каталог, контейнеры и тома уходят вместе, мусора не
      остаётся
- [ ] Измерить и записать, сколько стендов машина держит одновременно
      (ADR-045 ограничивает четырьмя агентами по той же причине)
- [ ] Обновить [DEPLOY.md](DEPLOY.md) §2 и [CLAUDE.md](CLAUDE.md) под новый
      порядок запуска
- [ ] Проверка: после сноса `docker volume ls` и `git worktree list` чистые;
      `pnpm check` в worktree ловит ошибку, внесённую только в него

**Когда готова:** Заведение и снос — по одной команде; проверки в worktree
идут по его собственному коду.

### Фаза 3: Хук работает в worktree

**Цель:** Коммиты из разных worktree не накладываются, а тесты идут в свой
стенд, а не в чужой.
**Затрагивает:** инфраструктура

**Задачи:**

- [ ] Перевести замок хука на `--git-common-dir`: в worktree
      `git rev-parse --git-dir` даёт `.git/worktrees/<имя>`, и замок ADR-163
      перестаёт быть общим
- [ ] Направить тесты хука в стенд своего worktree
- [ ] Проверка: одновременный коммит в двух worktree приводит к ожиданию, а
      не к наложению; остановка чужого контейнера не ломает свой коммит

**Когда готова:** Замок виден из обоих worktree; коммит проверяется своим
стендом.

### Фаза 4: Задача проходит маршрут целиком

**Цель:** Ветка, Pull Request и merge перестают быть теорией: одна настоящая
задача проходит путь от issue до закрытия.
**Затрагивает:** процесс

**Задачи:**

- [ ] Завести шаблон Pull Request: что сделано, какой issue закрывает, чем
      проверено
- [ ] Сделать прогон `/code-review` обязательным гейтом до merge
- [ ] Провести одну задачу целиком: issue → ветка → коммиты → PR → merge
- [ ] Проверка: `Closes #N` закрыл issue сам, ветка удалена после merge

**Когда готова:** Задача закрыта merge'ем, а не руками; в `main` попало
только то, что прошло гейт.

### Фаза 5: main под защитой

**Цель:** Правило «в `main` не коммитят напрямую» держится машиной, а не
памятью.
**Затрагивает:** инфраструктура

**Задачи:**

- [ ] Включить защиту `main`: прямой push отклоняется, обязательная
      проверка — CI (только после починки красного пайплайна, issue #94)
- [ ] Заготовить workflow выкладки при merge — выключенным до появления VPS
- [ ] Проверка: попытка прямого push в `main` отклонена; PR с красным CI не
      сливается

**Когда готова:** Прямой push в `main` невозможен; merge требует зелёного CI.
