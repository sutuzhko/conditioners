## Где проект

Сайт — **лендинг с товарными адресами**: главная со всеми коммерческими
секциями, каталог и страницы моделей (ADR-109 отменил часть ADR-049), База
знаний, политика и закрытая админка. Кластер отдельных посадочных страниц
по-прежнему удалён — вернуть его можно только новым ADR.

- Публичные маршруты: `/`, `/catalog`, `/catalog/[slug]`, `/compare`,
  `/knowledge`, `/knowledge/[slug]`, `/privacy`
- Панель: сводка, календарь работ, заявки, клиенты, заказы, склад,
  монтажники, компания, каталог, цены, статьи, отзывы, уведомления, профиль
- Ролей две: владелец видит всё, монтажник — свои наряды, календарь и
  профиль (ADR-092, ADR-095, ADR-114)
- 263 файла тестов, 2865 тестов зелёные (`pnpm check` — линт, стили, типы, тесты)
- 38 сквозных Playwright в двух профилях (`pnpm --filter web e2e`), включая
  три обязательных сценария CLAUDE.md: заявка с проверкой в БД, отзыв →
  модерация, правка цены → цена на сайте
- Снимки историй Storybook работают (`pnpm --filter web vr`), эталонов в
  репозитории нет — решение о хранении за владельцем
- Разработка в Docker (ADR-017), сайт на `http://localhost:3000`
- Боевой состав описан: `docker-compose.prod.yml`, `Caddyfile`, `infra/*.sh`

### Чем это далось — читать до того, как звать агентов

🔴 **Четыре фоновых агента, четыре смерти, ни одного отчёта.** Причина одна и
воспроизводимая: контейнеру выделено 4 ГБ и 5 ядер, и агент, гоняющий тесты
или браузерную пробу, либо упирается в таймаут инструмента, либо роняет
контейнер по памяти вместе с собой. Инструмент при этом продолжает
показывать агента живым — «running» полтора часа при пустом транскрипте.

Что из этого следует:

- **Проверять дерево, а не список агентов.** `find -newermt` по рабочему
  каталогу и время правки транскрипта отвечают на вопрос «жив ли он» честно.
- **Не гонять тесты одновременно с агентом.** Один полный прогон занимает
  контейнер целиком; два убивают его.
- **Браузерные пробы с таймаутами по 5–10 минут писать нельзя.** Именно на
  них встали три агента: 4 страницы × 4 ширины × 2 темы при холодном
  дев-сервере — это десятки минут.
- **Работа агентов принимается по дереву.** В сданном коде нашлись и хорошие
  решения (предохранитель сида, правило «статус + исполнитель» одно на три
  места), и дефекты: устаревший двойник в тесте маршрута, типы, падавшие под
  `exactOptionalPropertyTypes`, неполная починка редиректа.

**Playwright MCP работает** — на macOS сеть жива, `npx @playwright/mcp@latest
install-browser chrome-for-testing` ставит браузер. Вынужденное отступление на
раннер (ADR-103) закончилось.

**В журнале решений было два ADR-149** — второй переименован в ADR-150,
ссылка в этом файле поправлена.

### С нуля на другой машине

Репозиторий самодостаточен намеренно (ADR-150): правила, скиллы, на которые
они ссылаются, и настройка MCP лежат внутри. Не лежит внутри ровно одно —
секреты и данные, и это правильно.

```bash
git clone git@github.com:sutuzhko/conditioners.git && cd conditioners
cp .env.example .env                      # заполнить POSTGRES_*; остальное — из compose
docker compose -f docker-compose.dev.yml up -d
docker compose -f docker-compose.dev.yml exec -T web pnpm --filter web exec prisma migrate deploy
docker compose -f docker-compose.dev.yml exec -T web pnpm seed
docker compose -f docker-compose.dev.yml exec -T web pnpm seed:demo
```

Сайт поднимется на `http://localhost:3000`, панель наполнится демо-данными,
пароль всех демо-монтажников — `demo-parol-2026`.

**Что придётся сделать руками, потому что в репозитории этого нет и быть не
должно:**

| Чего нет                | Откуда взять                                                              |
| ----------------------- | ------------------------------------------------------------------------- |
| `.env`                  | `cp .env.example .env`. В деве это три значения `POSTGRES_*` без секретов |
| `.env.prod`             | только на боевом сервере, см. [DEPLOY.md](DEPLOY.md)                      |
| Загруженные фото        | живут в томе Docker; `pnpm seed:demo` кладёт демо-набор заново            |
| Браузер для MCP         | `npx playwright install chromium` — нужна сеть (ADR-148)                  |
| Авторизация `gh`        | `gh auth login`, если понадобится разбор CI                               |
| Эталоны снимков историй | их нет ни у кого: решение о хранении за владельцем, см. вопрос 1 выше     |

🔴 **Симлинки `.claude/skills/*` ведут в `.agents/` и хранятся в git режимом
`120000`.** На Linux и macOS разворачиваются сами. На Windows **вне WSL** git
без `core.symlinks=true` положит вместо них текстовые файлы с путём — скиллы
не подхватятся. В WSL всё работает как на Linux.

Проверка перед коммитом — в контейнере, не на хосте:

```bash
docker compose -f docker-compose.dev.yml exec -T web pnpm check
```

## Что знать до первой правки

- **🔴 Никакой транслитерации в адресах.** Ни в маршрутах, ни в якорях, ни в
  параметрах запроса: `#lead`, а не `#zayavka`; `?category=`, а не
  `?rubrika=` (инвариант 17). Русскими остаются только слаги статей,
  которые задаёт владелец.
- Навигация ведёт на `/#якорь`, а не `#якорь`: те же ссылки стоят в шапке
  страниц статей, где голый якорь вёл бы в никуда.
- **Git — только у оркестратора** (ADR-044). Агенты к нему не подходят:
  индекс общий, и параллельные коммиты сметают чужие файлы.
- **Не больше четырёх агентов сразу** (ADR-045) — машина не вытягивает.
- Коммит: `git commit -- <пути>`, а не `git add` со всем индексом (ADR-032).
  Пути со скобками — в кавычках, иначе zsh их проглотит и коммит станет пустым.
  Новые файлы так не закоммитить: `git commit -- <путь>` знает только то, что
  уже отслеживается, — их придётся сначала добавить точечным `git add <пути>`
  (запрещён именно `git add` всего индекса, а не сама команда).
- История не переписывается (ADR-033). `--amend` чужого коммита запрещён.
- Упоминаний ИИ в коммитах быть не должно, включая соавторство.
- CSS Modules изолируют имена, но не каскад: при равной специфичности
  выигрывает порядок сборки (ADR-038). Отсюда удвоенные классы в коде.
- Отступления от макета перечислены в [PIXEL_SPEC.md](PIXEL_SPEC.md).
  Они осознанные — «чинить» их обратно не нужно.
- Удалили страницу — почистите `.next/types/app/(site)/<имя>`: `tsc` иначе
  ругается на несуществующий модуль из старого сгенерированного типа.
- Разметка не собирается, пока в настройках стоят заглушки «ЗАПОЛНИТЕ В
  АДМИНКЕ»: `text()` в `shared/seo/schema.ts` отбрасывает их намеренно. Это не
  дефект — проверять JSON-LD нужно на заполненных данных (см. тест лендинга).
- **Стенд наполняется одной командой:** `pnpm seed:demo` (ADR-118). Компания,
  каталог с фотографиями, статьи, монтажники, клиенты, обращения, отзывы,

  пропадает молча. Ловится только браузером — в jsdom порядок событий другой.
- 🔴 **Клик в тесте браузера до гидратации уходит в обычный переход**, и
  модальное окно не рисуется: страница отвечает 200, окна нет, и выглядит
  это как сломанный перехватывающий маршрут. Перед кликом нужна пауза после
  `networkidle` — иначе диагноз будет ложным (проверено дважды).
- 🔴 **Свежая миграция не видна дев-серверу без перезапуска.** `next dev`
  держит в памяти клиент Prisma, сгенерированный до неё, и любой маршрут по
  новым таблицам падает с «Cannot read properties of undefined (reading
  \'findMany\')». Лечится `docker compose -f docker-compose.dev.yml restart web`
  — это не дефект кода, и искать его в репозитории бесполезно.
- **`prisma migrate dev` в контейнере не работает при предупреждении** (новый
  уникальный индекс, потеря колонки): команда интерактивна и падает с «non-
  interactive environment». Обход — сгенерировать SQL
  (`prisma migrate diff --from-schema-datasource --to-schema-datamodel
--script`) в папку миграции и применить `prisma migrate deploy`.

## Чего нет и почему

| Чего нет                             | Почему                                                                                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Эталонов снимков в репозитории       | Порядка тысячи PNG; хранить ли их — решение владельца                                                                                                  |
| Запуска вне Docker                   | `pnpm install` на хосте отдаёт пустой `node_modules` (ADR-028)                                                                                         |
| Карты на контактах                   | Решение о встраивании отложено                                                                                                                         |
| Автодеплоя с пуша                    | Сознательно: на проекте одного разработчика рисков больше, чем экономии                                                                                |
| Отдельных посадочных страниц         | Сайт — лендинг (ADR-049). Каталог и страницы моделей вернулись отдельным решением (ADR-109); гео-страницы по районам — только с уникальным содержанием |
| Реестра образов                      | Сборка идёт на сервере; реестр — решение владельца, когда VPS станет мало                                                                              |
| Напоминаний о делах календаря        | Сначала нужен сам график: уведомлять о делах, которых никто не завёл, не о чем (ADR-080)                                                               |
| Нескольких снимков в отзыве          | Форма принимает по одному фото автора и места установки; решение за владельцем                                                                         |
| Партий, FIFO и штрихкодов            | Сознательно вне первой версии склада: себестоимость решается вместе с §8.2, а не половинкой (ADR-134)                                                  |
| Поштучного учёта техники             | Серийные номера пишутся в движении текстом; экземпляр как запись тянет партии и резервирование (ADR-134)                                               |
| Разбора накладной поставщика         | Приход заводится руками: у каждого поставщика свой формат, а работающий склад дороже удобного ввода (ADR-134)                                          |
| Публичного JSON-API                  | Потребителя нет; появится — появится и контракт (ADR-122)                                                                                              |
| Поиска по календарю и горячих клавиш | Осознанно вне первой версии переделки (ADR-140); там же многодневные записи и перетаскивание по горизонтали                                            |
