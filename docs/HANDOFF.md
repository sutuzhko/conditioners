## Где проект

Сайт — **лендинг с товарными адресами**: главная со всеми коммерческими
секциями, каталог и страницы моделей (ADR-109 отменил часть ADR-049), База
знаний, политика и закрытая админка. Кластер отдельных посадочных страниц
по-прежнему удалён — вернуть его можно только новым ADR.

- Публичные маршруты: `/`, `/catalog`, `/catalog/[slug]`, `/compare`,
  `/knowledge`, `/knowledge/[slug]`, `/privacy`
- Панель: сводка, календарь работ, заявки, клиенты, заказы, склад,
  монтажники, компания, каталог, цены, статьи, отзывы, уведомления, профиль
- Ролей две: владелец видит всё, монтажник — свои наряды, календарь и
  профиль (ADR-092, ADR-095, ADR-114)
- 314 файлов тестов, 3447 тестов зелёные — **`pnpm check` из корня**
  (линт, стили, типы, тесты)
- 🔴 **`pnpm --filter web check` проверкой не является.** Форма стояла в
  документации год и выходила **с кодом 0**, ничего не запустив: скрипта в
  воркспейсе не было. Отчёт «прогнал, зелено» по ней был пустым (ADR-189)
- 27 сквозных Playwright в двух профилях, включая три обязательных сценария
  CLAUDE.md: заявка с проверкой в БД, отзыв → модерация, правка цены → цена
  на сайте. 🔴 Гонять их **`pnpm e2e:stand`**, а не `pnpm e2e`: стенд
  поднимает отдельную базу `db-test`, тогда как `e2e` пойдёт в дев-базу с
  настоящими обращениями владельца ([DEPLOY §2.3](DEPLOY.md))
- Снимки историй Storybook сравниваются с кадрами базы `merge-base`, снятыми
  в той же работе пайплайна тем же образом (`vr`, `vr-panel`; ADR-230).
  Эталонов в репозитории нет и пересчитывать их не нужно: расхождения — в
  сводке работы и в артефакте, задуманное изменение принимается ярлыком
  `vr:accepted` на PR, отказ сценария красит всегда. 🔴 Кадры с macOS ни с
  чем не сойдутся — шрифты другие: смотреть вёрстку через Playwright MCP,
  сравнивать — в CI
- Инварианты раскладки без эталона — работа `invariants` (четыре шарда и
  сводная), все истории включая `Админка/`, обе темы: переполнение, размер
  целей, тема, обрезанный текст, накрытие, шрифты, картинки (ADR-230, фаза 3).
  Локально против витрины: `pnpm --filter web vr:invariants`; правила и их
  тесты на живом DOM — `e2e/vr/invariants/`. Допущение — параметром истории с
  причиной. 🔴 В защиту `main` работа пока не входит — решение владельца после
  разбора нарушений (#457)
- Измерения раскладки текстом — работа `measure` (четыре шарда и сводная):
  файл на историю в `apps/web/e2e/vr/measurements/`, сравнение с допуском 1px,
  любое расхождение — красный, пока файлы не обновлены (ADR-234). Обновить —
  `pnpm --filter web vr:measure:pull` (артефакт `measurements-updated`
  последнего прогона ветки; нужен `gh`). Локально: витрину поднимать с
  `VR_STABLE_CLASSNAMES=1`, иначе ключи узлов — хешированные классы
- Пайплайн гоняет `check`, `e2e`, `vr`, `vr-panel`, `invariants` и `measure`.
  Прежняя запись «CI не гоняет сквозные и снимки» устарела. Сквозные идут
  четырьмя группами на своих раннерах, `e2e` — сводный вердикт над ними
  (ADR-242). 🔴 Новый spec-файл приписывается к группе в
  `scripts/e2e-groups.mjs`, иначе `check` и `e2e` красные с именем файла.
  Сценарии не гоняются там, где правка их не задевает (перечень путей —
  `scripts/e2e-scope.mjs`), и не повторяются для кода, который уже прошёл:
  маркер в кеше Actions по ключу содержимого, журнал работы называет ключ и
  прогон-источник (ADR-243)
- Два режима разработки: полный состав в Docker (ADR-017) и база в контейнере
  при приложении на хосте (ADR-173). Сайт на `http://localhost:3000`
- Боевой состав описан и **прогнан локально на пустой базе** 30 августа
  (issue #114, #62, #104): `docker-compose.prod.yml`, `Caddyfile`, `infra/*.sh`

## Что сделано в последнюю очередь (2–3 сентября 2026)

Раздел живёт до следующей крупной работы — потом его заменяют новым.

### 2–3 сентября: обе «Фазы 6» закрыты, работа шла двумя подрядчиками

Смена шла оркестратором и двумя подрядчиками в отдельных worktree. Влито
два PR (#493 «Резина · Фаза 6», #494 «Панель · Фаза 6»), закрыто тринадцать
issue: #269–#273, #334, #336–#338 и четыре находки замеров панели —
#366, #367, #369, #373.

🔴 **Четыре issue закрылись замером, а не работой.** Контраст панели и
тап-зоны оболочки числились красными с 31 августа, хотя правки уже лежали
в `main`: `admin-contrast.mjs` на текущей вершине даёт 0 нарушений на 2756
узлах в тринадцати разделах и обеих темах, `admin-density.mjs` — 0
расхождений плотности и только три известные цели #376. **Первое, что стоит
делать с унаследованным списком дефектов, — перемерить его**, а не чинить по
описанию: описание могло устареть на неделю.

**Публичная часть, «Резина · Фаза 6» (#269–#273).** Объясняющие блоки
перестали занимать по два экрана: шаги монтажа сеткой «номер — описание» с
`min-width: 0` (описания резались правым краем), «День монтажа по часам» и
список второй сметы свёрнуты родным `<details>` до 900px и раскрыты стилем
через `::details-content` дальше, симптомы сервиса — сеткой 2×3 вместо ленты,
которая прятала четыре пункта из шести. Всё это ADR-237.

**Панель, «Фаза 6» (#334, #336–#338).** У блока данных появились три
состояния как общее правило: `ErrorState` в ките той же анатомии, что
`EmptyState`, `DataBlock` с `Suspense` и границей ошибки (ADR-238),
скелетоны в геометрии готовой страницы (ADR-239), фокус не уходит под липкие
шапку и полосы действий (ADR-240), карточка готовности сводки стоит
последней всегда (ADR-241).

### Чему научила эта смена

🔴 **Ревью нашло то, чего не видели ни тесты, ни глаза, ни замеры — и оба
раза это была «дырка в проверке», а не дефект вёрстки.**

1. **Истории нового компонента не проверялись ничем.** Раздел назывался
   `Кит панели/`, а списки разделов у снимков, инвариантов и измерений зашиты
   префиксами `UI Kit/`, `Кит/`, `Админка/`. Три истории `DataBlock` —
   загрузка, данные, ошибка, то есть весь смысл issue #336 — не снимались, не
   мерились и не проверялись, и **ни одна работа об этом не сообщала**.
   Проверять надо не «зелено ли», а «попало ли в список»: `measure` молча
   пропускает то, чего не видит.
2. **Скелетон повторял только одно состояние данных.** Карточка готовности
   сводки переезжала наверх, пока настройки не заполнены, — а у скелетона
   данных нет, и он рисовал случай «готово». На ненастроенном сайте плитки
   уезжали вниз на 180–250px сразу после загрузки: прыжок первого экрана
   ровно в том состоянии, ради которого карточку и поднимали. Лечится не
   скелетоном, а разметкой: позиция блока не должна зависеть от данных
   (ADR-241).

🔴 **Своя граница ошибки обязана пропускать ошибки роутера.** `redirect()`,
`notFound()` и `forbidden()` серверного компонента приходят в
`getDerivedStateFromError` обычным исключением. Поймать их — значит показать
карточку «Не удалось загрузить» вместо перехода или 404, а на проверке
доступа (ADR-095) оставить человека в чужом разделе. Лечится
`unstable_rethrow` из `next/navigation` первой строкой — так делает и сама
граница Next.

🔴 **Сценарий, зелёный локально и красный в CI, чинится по артефакту, а не
по догадке.** Три сквозных сценария падали в CI дважды подряд, и обе догадки
— «данные разошлись» и «раскладка кусков потока» — оказались мимо. Ответ дал
`gh run download <id> -n e2e-trace`: `error-context.md` печатает дерево
страницы на момент падения, и по нему сразу видно, чего на экране не было.
Настоящих причин было две, обе про время, а не про данные: заготовка
`Suspense` в поток не попала вовсе (гонка) и управляемый список откатывал
выбор, сделанный до гидратации.

**Стенд перед сдачей сценариев сбрасывают поимённо.** База стенда —
`docker compose -f docker-compose.dev.yml --profile test rm -sfv db-test`;
🔴 форма с `down -v` сносит тома всего проекта, включая дев-базу владельца —
именно так она и была потеряна в эту смену.

**Подрядчики обрываются на ошибках API, и это норма.** За смену агенты
падали пять раз на `403 authentication_failed` и `429 session limit`. Работа
в worktree при этом цела — теряется только контекст агента. Возобновлять
надо `SendMessage` тому же агенту, обязательно приложив `git status` его
worktree и сказав «перечитай свои правки, не начинай заново»: иначе он
переделает первый шаг.

### Что осталось нерешённым и ждёт владельца

- 🔴 **Высотные бюджеты не выполнены — issue #429.** Цены на 375 дают 1742px
  при норме 1400, экономия 1395px при норме 850. Бюджеты противоречат
  требованиям вёрстки из тех же issue; сокращать остаётся содержание, а это
  решение владельца (ADR-215).
- 🔴 **Защита `main` не включена** (#169). Обязательными делаются `check`,
  `e2e` и `vr`; «ветка свежая» — выключено (при получасовом `vr` и двух
  подрядчиках каждый PR иначе вечно догоняет); обход админом оставлен на
  инциденты; PR обязателен без апрува — иначе соло-владелец сам себя не
  одобрит и заблокируется. Ставится через
  `gh api -X PUT repos/sutuzhko/conditioners/branches/main/protection`.
- **Вторая копия бэкапа в хранилище РФ** (#397): нужен провайдер, доступы и
  согласие на новую зависимость.
- 🔴 **Данные дев-базы потеряны 3 сентября** и восстановлены только сидами:
  всё, что владелец заводил в панели поверх демо-набора, и все загруженные
  файлы. Причина — `--profile test down -v`: профиль выбирает, какие сервисы
  поднимать, но `down -v` сносит тома всего проекта. Разбор в
  [BUGS.md](BUGS.md); безопасная форма —
  `docker compose -f docker-compose.dev.yml --profile test rm -sfv db-test`.

### Дефекты, которые нашлись — и ни один не был виден на глаз

🔴 **Сайт не поднялся бы на первом деплое.** `server.js` из standalone слушает
адрес из `process.env.HOSTNAME`, а Docker кладёт туда идентификатор
контейнера: приложение вставало на `172.18.0.3:3000` и только там,
healthcheck по `127.0.0.1` отвечал refused вечно, а `caddy` с
`depends_on: service_healthy` **не стартовал вовсе**. Сайта не было бы ни по
http, ни по https при полностью исправном приложении. В деве не
воспроизводится никаким старанием — нашла репетиция боевого состава.

🔴 **`.env.local` разработчика уезжал в контекст сборки и в образ воркера.**
В `.dockerignore` шаблоны стояли без `**`, а такой шаблон совпадает только с
корнем. Дев-пароль базы и секрет сессии лежали в образе, а `next build` читал
оттуда всё незаданное — включая `NEXT_PUBLIC_*`, которые идут в клиентский
бандл. Сегодня они пусты, так что не утекло ничего. Это везение, а не
устройство.

🔴 **Лента отзывов при `prefers-reduced-motion` замирала навсегда.** Прокрутка
у неё выключена (её двигает только компонент), и остановка не возвращала её:
ни колесом, ни пальцем, ни полосой. Отзывы правее первого экрана становились
**недостижимы ровно для того человека, ради которого лента и
останавливалась** — в HTML они есть, робот их видит, а прочитать нечем.

🔴 **Обложка статьи резалась на 16,7%.** Компонент объявлял 1200×525 —
«пропорция из макета», — а загрузчик ужимает картинку `fit: 'inside'`, то
есть сохраняет соотношение сторон исходника. Настоящая обложка приходит
1200×630, и рамка резала её поровну сверху и снизу, ровно по строке подписи.

🔴 **Словарь статусов панели жил по месту в семи файлах.** Расхождения не
косметические: «Отказ» в журнале доставки шёл **краской скидки**, «Назначен»
рисовался плашкой, какой в словаре нет, карта статусов заявок существовала в
двух разошедшихся копиях. Закрыт шестью красками в домене (ADR-194), новый
статус без краски роняет прогон.

🔴 **Кнопка кита роняла панель.** Оборачивала `onClick` всегда, даже когда его
не передали, — а функция в пропсах серверного компонента не сериализуется.
`/admin/orders` открывался экраном «Сайт временно не отвечает».

**Замеры, которых не видно снимком.** Слот под скидку в карточке давал
разброс 22px — цена плясала по ряду; после починки «Заказать» стоит на 351px
у всех трёх карточек. Вторая половина того же дефекта нашлась на странице
модели: междустрочный интервал строки цены был задан в пикселях, коробки
сравнялись, а выносные элементы нет (ADR-198). Замеры контраста и плотности
панели на живом DOM дали 62 нарушения контраста (худшее 1,12:1 при норме 3:1)
и 85 расхождений плотности — на всё заведены issue.

### Что это говорит о процессе

**Журнал отстаёт от кода, а не врёт.** Сверка всех 222 записей с кодом
(issue #120): из 152 закрытых **ни одна не приписала себе несделанного**.
Зато 22 записи стояли красными, хотя починены, а у двух съехали заголовки —
читатель получал чужой текст. Две задачи из трёх в инфраструктурной гигиене
оказались давно сделанными.

🔴 **Проверка, которая молча проходила.** `pnpm --filter web check` выходил с
кодом 0, ничего не запустив: скрипта в воркспейсе не было. Год документация
предписывала форму, по которой любой отчёт «зелено» был пустым (ADR-189).
Поймано двумя подрядчиками независимо.

🔴 **Рабочие копии попадали под линтер.** `.claude/worktrees/` не был закрыт
ни от ESLint, ни от git: `pnpm check` на чистом `main` давал 494 ошибки при
зелёном CI, все чужие, — а один `git add -A` унёс бы в коммит несколько
чекаутов репозитория (issue #417).

### Чем это далось — читать до того, как звать агентов

**Подрядчики работают хорошо, если давать им контекст и границы.** Оба
подрядчика этой смены сдали работу с числами из браузера, назвали свои
отступления от макета поимённо и **сами перечислили несделанное**, не дожидаясь
вопроса. Один нашёл собственное неверное утверждение и исправил его в PR, а не
только в отчёте.

Что для этого делалось:

- **В задание кладётся контекст, а не только список issue.** Какие ADR уже
  приняты и что из них следует, где грабли (пересчёт эталонов, общая база при
  своих каталогах загрузок), какие номера ADR заняты.
- **Границы называются заранее.** «Мержить не надо», «эти файлы не трогай»,
  «упрёшься в решение — заводи ADR и пиши мне, а не выдумывай».
- 🔴 **Номера ADR раздаёт оркестратор.** Два подрядчика взяли 193
  одновременно — разведено при сведении. Диапазон выдавать в задании.
- **Ветки не должны стоять стопкой дольше суток.** Кит общий с публичной
  частью, и как только он поехал, **все** ветки каталога стали конфликтными
  разом — конфликт только в бинарных эталонах снимков.
- **Пересчёт эталонов — полчаса.** Пять веток подряд это два с половиной часа,
  где каждый следующий прогон обесценивает предыдущий. Сводить в одну ветку и
  считать один раз.

## Открытые вопросы к владельцу

Блокирующих вопросов сейчас нет. Ждут без блокировки:

0. 🔴 **Переезд на NestJS — до запуска сайта или после.** Решение «переезжаем,
   когда полностью закончим с фронтом» принято 30 августа (ADR-192), но оно

должно:**

## Что знать до первой правки

- **🔴 Никакой транслитерации в адресах.** Ни в маршрутах, ни в якорях, ни в
  параметрах запроса: `#lead`, а не `#zayavka`; `?category=`, а не
  `?rubrika=` (инвариант 17). Русскими остаются только слаги статей,
  которые задаёт владелец.
- Навигация ведёт на `/#якорь`, а не `#якорь`: те же ссылки стоят в шапке
  страниц статей, где голый якорь вёл бы в никуда.
- **Git — только у оркестратора** (ADR-044). Агенты к нему не подходят:
  индекс общий, и параллельные коммиты сметают чужие файлы.
- 🔴 **`down -v` сносит тома всего проекта, и профиль этого не меняет.**
  `--profile test down -v` 3 сентября удалил дев-базу владельца, загруженные
  файлы и кеши вместе с базой стенда. База стенда сносится поимённо:
  `docker compose -f docker-compose.dev.yml --profile test rm -sfv db-test`
  (плюс `docker volume rm conditioner-dev_pgdata_test`, если нужен и том).
  Ни одна команда с `-v` не уходит в задание подрядчика без имени сервиса.
- 🔴 **Своя граница ошибки обязана пропускать ошибки роутера.**
  `redirect()`, `notFound()` и `forbidden()` серверного компонента приходят
  в `getDerivedStateFromError` обычным исключением: поймать их — значит
  показать «Не удалось загрузить» вместо перехода или 404, а на проверке
  доступа (ADR-095) оставить человека в чужом разделе. Первой строкой —
  `unstable_rethrow` из `next/navigation`, как делает граница самого Next.
- 🔴 **Скелетон `Suspense` попадает в поток не всегда.** Если данные успели
  прийти к первому сбросу, React отдаёт сразу готовый контент, и заготовки в
  HTML нет вовсе — гонка сервера с самим собой, которая по-разному
  складывается на прогретой машине и на холодной сборке в CI. Отсюда правило:
  **состояние загрузки сквозным сценарием не проверяется**, его геометрию
  сторожат истории `Админка/Скелетоны разделов` и их измерения. Задержка
  RSC-ответа при клиентском переходе тоже не помогает: в dev Next не
  префетчит ссылки, и задержка держит на экране прежний раздел (замерено).
- **Не больше четырёх агентов сразу** (ADR-045) — машина не вытягивает.
- Коммит: `git commit -- <пути>`, а не `git add` со всем индексом (ADR-032).
  Пути со скобками — в кавычках, иначе zsh их проглотит и коммит станет пустым.
  Новые файлы так не закоммитить: `git commit -- <путь>` знает только то, что
  уже отслеживается, — их придётся сначала добавить точечным `git add <пути>`
  (запрещён именно `git add` всего индекса, а не сама команда).
- История не переписывается (ADR-033). `--amend` чужого коммита запрещён.
- Упоминаний ИИ в коммитах быть не должно, включая соавторство.
- CSS Modules изолируют имена, но не каскад: при равной специфичности
  выигрывает порядок сборки (ADR-038). Отсюда удвоенные классы в коде.
- Отступления от макета перечислены в [PIXEL_SPEC.md](PIXEL_SPEC.md).
  Они осознанные — «чинить» их обратно не нужно.
- Удалили страницу — почистите `.next/types/app/(site)/<имя>`: `tsc` иначе
  ругается на несуществующий модуль из старого сгенерированного типа.
- Разметка не собирается, пока в настройках стоят заглушки «ЗАПОЛНИТЕ В
  АДМИНКЕ»: `text()` в `shared/seo/schema.ts` отбрасывает их намеренно. Это не
  дефект — проверять JSON-LD нужно на заполненных данных (см. тест лендинга).
- **Стенд наполняется одной командой:** `pnpm seed:demo` (ADR-118). Компания,
  каталог с фотографиями, статьи, монтажники, клиенты, обращения, отзывы,
  наряды, календарь, занятость и журнал доставки — всё сразу и заново при
  каждом запуске. Пароль всех демо-монтажников — `demo-parol-2026`.
  🔴 Это не миграция и не может ею быть: `migrate deploy` идёт и на боевом
  сервере, а здесь выдуманная компания и ПДн несуществующих людей. Скрипт
  отказывается работать при `NODE_ENV=production` и при `https` в `SITE_URL`.
  После сброса базы порядок такой: `prisma migrate deploy` → `pnpm seed` →
  `pnpm seed:demo`.
- **Сборка образа ходит в базу.** Главная, политика и статьи пререндерятся с
  данными, поэтому `next build` без живой базы падает — так и задумано
  (ADR-062). Формальные значения ENV на время сборки — в `Dockerfile`.
- **Сборка сама ставит `NODE_ENV=production`** (ADR-104) — переписывать
  скрипт «обратно на `next build`» не нужно. В контейнере переменная задана
  как `development` ради `next dev` и воркера, а `next build` её не
  перебивает: рантайм страниц у бандла и у воркера экспорта расходится, и
  Next печатает невнятное «Html should not be imported outside of
  pages/\_document» на пререндере 404. Задать `SITE_URL` всё же придётся:
  `SITE_URL=https://build.invalid pnpm --filter web build` — схема ENV в
  production не принимает http стенда (ADR-102).
- Сквозные сценарии: `pnpm --filter web e2e` в контейнере. Браузер системный
  (`CHROMIUM_PATH`), воркер один — рядом живут дев-сервер и Storybook.
- 🔴 **Прыжок вёрстки проверяется измерением, а не снимком.** Снимок
  показывает одно состояние; вопрос «двигается ли кнопка, когда меняется
  соседний блок» он не решает вовсе. 28 августа резерв под скидку в подборе
  выглядел готовым на глаз и на снимке, а измерение координаты кнопки при
  движении ползунка показало разброс в 22px на 320px. Приём: одноразовый
  сценарий гоняет ползунок по значениям и печатает `getBoundingClientRect()`
  контрольного элемента; «стоит на месте» — это одно число во всех
  состояниях, а не впечатление.
- **Одноразовая проба Playwright:** файл `.mts` рядом с `apps/web`, запуск
  `npx tsx <файл>.mts` из `/app/apps/web`,
  `chromium.launch({ executablePath: process.env.CHROMIUM_PATH })`, адрес
  `http://localhost:3000`. 🔴 **Пробу обязательно удалить после проверки:**
  `console.log` в ней валит `pnpm lint` (`no-console`), и упавшие агенты уже
  дважды оставляли такие файлы — полный прогон падал не на коде, а на мусоре.
- **`pnpm shot` не умеет снимать элемент** — только страницу целиком или
  экран. Для снимка одного блока (карточка подбора, форма) нужна та же
  одноразовая проба с `locator.screenshot()`.
- **В дев-базе ровно одна модель с действующей скидкой** —
  `split-sistema-09-invertor`, до 27 м². Всё, что проверяет ветку скидки,
  обязано попасть именно на неё: на 25 м² подбор выдаёт базовую девятку без
  скидки, на 30 м² — двенадцатую. Проба, гулявшая по «круглым» площадям,
  скидку не увидела ни разу и отчиталась зелёным.
- Перед снимками историй (`pnpm --filter web vr`) перезапустите контейнер
  `storybook`: Vite держит кеш зависимостей, и после установки пакетов истории
  отдают «504 Outdated Optimize Dep», а снимок выходит пустым, а не упавшим.
- Секрет вебхука Telegram — только ASCII: кириллица в HTTP-заголовок не
  помещается, и такой вебхук Telegram не примет.
- **Кольцо фокуса задаётся формой элемента, а не общим правилом** (ADR-085).
  Кликабельный элемент поверх карточки берёт её радиус через
  `border-radius: inherit`; элемент внутри контейнера с `overflow: hidden`
  или маской получает кольцо внутрь (`--ring-focus-inset`) и радиус
  контейнера. Глобальное правило для текстовых ссылок завёрнуто в `:where()` —
  разворачивать обратно нельзя, оно перебьёт радиусы всех компонентов.
- **Время в календаре работ — всегда московское** (ADR-080). Момент хранится
  в UTC, а день и час считает `shared/lib/calendar` в поясе города. Прямых
  `new Date().getHours()` в календаре быть не должно.
- **Бюджет JS проверяется машиной** (ADR-088): `pnpm budget` после боевой
  сборки, в CI — со `--strict`. Порогов два: платформенный пол 105 КБ (рантайм
  Next и React, не наш код) и собственный слой 75 КБ на публичной странице.
  Числа скрипта на пару процентов ниже, чем у `next build`, — сравнивать нужно
  замеры одного инструмента.
- 🔴 **`pnpm check` не гоняет `prettier --check`, а pre-commit гоняет.**
  Линт, стили, типы и тесты проходят, а коммит падает на форматировании.
  Перед коммитом:
  `docker compose -f docker-compose.dev.yml exec -T web pnpm --filter web exec prettier --write "src/**/*.{ts,tsx,css}"`
  и то же для `docs/**/*.md` из корня рабочего пространства.
- 🔴 **Новая миграция Prisma обязана попасть в коммит.** `.gitignore` держит
  правило `*.sql` для дампов, миграции выведены из-под него исключением —
  проверяйте `git status`, а не полагайтесь на память: игнорируемый файл в
  нём не показывается по определению (BUGS, 25 августа).
- **Справочник характеристик — подсказка, а не список допустимых значений.**
  Поле названия остаётся обычным текстовым, `datalist` только предлагает
  (ADR-094). Проверять по нему на сервере нельзя: инвариант 6 требует, чтобы
  владелец заводил характеристику, которой ещё нет.
- **🔴 Проверка доступа обязана стоять в самой странице** (ADR-095), а не
  только в layout: `redirect()` из layout отдаёт честный 307, но React к тому
  моменту уже отрисовал страницу параллельно, и её данные уезжают в теле
  ответа. Новая страница раздела владельца начинается с
  `await requireOwnerPage()` из `server/guards.ts`.
- **Константы, которые читает сервер, не живут в модулях с `'use client'`.**
  Next подменяет такой импорт ссылкой на клиентский код, и на сервере
  приходит пустое значение — так молча ломалась cookie колонки разделов.
- **Функции не переживают границу сервер→клиент.** Слот-проп
  (`renderForm` и подобные) из серверного компонента в клиентский роняет
  рендер всей страницы; композиция собирается в клиентском листе
  (`widgets/reviews/ReviewsCta.tsx` — образец). Юниты этого не видят —
  ловит только e2e.
- **Телефон приводится к одному виду `phoneKey`** (`shared/lib/phone`), и он
  же — ключ дедупликации клиента. Новый потребитель номера берёт эту функцию,
  а не пишет своё `replace(/\D/g, '')`: третья копия разойдётся с первыми
  двумя на первой правке (ADR-105).
- **Списки панели разбиваются `shared/ui/Pager`** — ссылками, без
  клиентского состояния: страница живёт в адресе. Поиск обязан переезжать
  вместе со страницей, иначе «Дальше» сбрасывает запрос.
- 🔴 **Цикл импортов `auth → repo/admin-users → http → auth`** ломает
  подмену сессии в интеграционных тестах: на полпути круга `http` получает
  настоящий `getAdminSession`, и проверка доступа уходит в `cookies()` вне
  запроса — падают все проверки файла с невнятным «cookies was called
  outside a request scope». Лечится подменой `@/server/repo/admin-users`
  в том же тесте (см. `app/api/admin/clients/route.test.ts`).
- **Локальная база может быть заведена мимо истории миграций.** Если
  `prisma migrate dev` предлагает сброс, а таблицы на месте — отметить
  прежние миграции применёнными (`prisma migrate resolve --applied <имя>`),
  а не сбрасывать: `reset` сотрёт данные владельца.
- **Админ-фичи ходят в API только через `adminRequest`**
  (`shared/lib/api.ts`): свой fetch-разбор в фиче — регресс аудита; 401
  обязан отличаться от отказа сервера.
- **`clientIp` один на проект** (`server/client-ip.ts`), первичен
  `X-Real-IP` от Caddy. Мутации админки сверяют Origin с Host — curl без
  Origin проходит, браузерный кросс-сайт нет.
- **Счётчик попыток входа fail-closed** (недоступна таблица — вход
  отказывает), у публичных форм — fail-open (инвариант 2). Это осознанная
  разница, ADR-097.
- **Заголовки безопасности — в `Caddyfile.headers`**, общем сниппете прод-
  и дев-прокси. Новый заголовок добавляется туда, а не в один из файлов.
- **E2E шлют настоящие Telegram-сообщения** (в `.env.dev` живой драйвер) и
  упираются в лимит входа 10/15 мин при полных прогонах подряд — пауза
  между прогонами обязательна.
- **`worker` и `migrate` работают под `nextjs`**, кеш corepack готовится
  при сборке (`COREPACK_HOME=/pnpm/corepack`) — иначе pnpm под непривилегированным
  пользователем полез бы в сеть на старте контейнера.
- **Момент рендера страницы один** (`now` в HomePage): скидки в разметке,
  JSON-LD и клиентском подборе считаются от одной точки (ADR-101). Новый
  потребитель `getActivePrice` на странице обязан получать тот же `now`.
- **🔴 Наряд урезается под роль в репозитории, а не в компоненте**
  (ADR-114). Монтажнику ключи цены, удержания и заметки владельца не
  приходят вовсе — они отсутствуют в ответе, а не спрятаны стилем. Новое
  владельческое поле наряда добавляется в проекцию `toCard`, иначе оно
  уедет монтажнику молча.
- **Чужой наряд монтажнику — `404`, а не `403`.** Репозиторий сужает выборку
  по `installerId` в самом запросе: существование чужого наряда монтажника
  не касается.
- **Оформление монтажника живёт в `shared/lib/employment.ts`.** Оно нужно и
  `entities/staff`, и `entities/order`, а импорт вбок между слайсами одного
  слоя запрещён — общее уходит вниз, в `shared`, а не копируется.
- **Маршруты нарядов сами шлют уведомления** (`server/notifications/orders`).
  Тесты этих маршрутов подменяют `@/server/db`, поэтому обязаны подменить и
  модуль уведомлений: иначе он пойдёт в неподменённые таблицы и маршрут
  ответит `500`. Предмет теста — маршрут, а не почтальон.
- **Контекст заявки копится в `sessionStorage['tk-lead-context']`** и
  разбирается единственной дверью `parseLeadContext` (ADR-133), которая
  ничего не бросает. Страница, показывающая цену, кладёт в снимок тот же
  `getActivePrice(product, now)`, которым рисует видимое число.
- **`nextjs: { appDirectory: true }` задан в `.storybook/preview.tsx`
  глобально.** Ставить его в отдельной истории не нужно: без глобального
  параметра падали все истории, трогающие роутер.
- 🔴 **Остаток склада — сумма движений, а не поле** (ADR-134). Ни одна схема
  и ни один маршрут не позволяют записать его напрямую: правка руками — это
  движение «инвентаризация» с обязательным основанием. Новый потребитель
  склада считает остаток агрегатом по журналу, а не читает колонку.
- **Архив склада — отдельный вид списка, и он достижим** (`?archived=1`).
  Позиция и зона сдаются в архив только пустыми; список без архива означал бы
  удаление без возврата.
- **Дробное количество форматирует `formatQuantity`** (`shared/lib/format`).
  Своей копии `Intl.NumberFormat` заводить нельзя: владелец сверяет письмо с
  экраном, и «4,3» против «4.3» заставит его усомниться в обоих.
- 🔴 **Единицы измерения — один словарь на проект** (`shared/config/units`),
  и подписи в нём несклоняемые сокращения. Остаток дробный: «0,5 баллона»,
  «2 баллона», «5 баллонов» — три формы, и `plural` их не даёт, потому что
  дробное число он разбирает как целое. Три копии словаря уже разошлись
  однажды: «бухт.», «бухт» и «бухта».
- **Создание в панели открывается `shared/ui/RouteModal`** — окном с
  собственным адресом на перехватывающем маршруте (ADR-117, ADR-141).
  Закрытие берётся хуком `useRouteClose`, своей копии правила шага назад в
  разделе быть не должно. Форма с введённым текстом сообщает окну `dirty` —
  иначе Escape унесёт заполненное молча.
- 🔴 **Переработка (`overtimeMin`) считается сервером при записи и только
  читается** (ADR-138). Пересчитать её при показе значит переписать прошлый
  четверг первой же правкой рабочего окна, а на эти минуты смотрят при
  расчётах с людьми. Рабочее окно — настройка `schedule` (минуты от
  московской полуночи), а не разбор строки `contacts.hours`.
- **Новый ключ настроек обязан получить русское название** в
  `widgets/admin-shell/summary-content.ts`. Иначе он доезжает до плашки
  готовности английским словом среди русских ярлыков — это ловит отдельная
  проверка, и она не зря стоит.
- 🔴 **Готовность настроек означает «сайт это покажет»**, а не «поле не
  пустое». Группа, которую отвергает её собственная схема, попадает в отчёт
  причиной `invalid`: публичная страница разбирает её той же схемой и при
  отказе берёт умолчания, то есть молча показывает пустоту.
- 🔴 **Что из реквизитов уходит наружу, решает `publicRequisites`**, и только
  она. Адрес регистрации предпринимателя тип отдаёт, а функция — нет: это
  домашний адрес. Новый потребитель реквизитов берёт эту функцию, а не лезет в
  `legal` полями.
  🔴 **Дверей у группы две:** страницы сайта и публичный маршрут
  `GET /api/settings/legal`. Вторую однажды забыли, и маршрут отдавал домашний
  адрес и банковские счета без всякой авторизации. Теперь он отдаёт проекцию
  (`publicValue` в `server/repo/settings-schemas`); утечку сторожат юнит и
  сквозной сценарий.
- 🔴 **Настройки компании — раздел владельца.** `/api/admin/settings*` стоят
  под `withOwner`: в группе персональные данные и адреса доставки уведомлений,
  а правка реквизитов меняет продавца на всём сайте. Закрывать раздел только
  страницей нельзя — адреса панели монтажник знает (ADR-092).
- 🔴 **jsdom не реализует `inert`.** Всё, что зависит от него — возврат фокуса
  после закрытия окна, недоступность фона для читалки, — юнит-тестом не
  проверяется вовсе: тест пройдёт на сломанном коде. Проверять браузером.
- **Реквизит в фикстуре обязан проходить контрольный разряд.** Иначе схема
  отвергнет группу, страница разберёт её с умолчаниями, и тест будет проверять
  пустоту, думая, что проверяет реквизиты. Уже случилось трижды.
- 🔴 **Фронтенд принимается глазами, а не тестами** ([CLAUDE.md](CLAUDE.md),
  «Как проверяется сделанное»). Зелёный `vitest` не говорит ни про уехавший
  за край элемент, ни про контраст, ни про прыгающее содержимое. Снимок
  страницы: `pnpm --filter web shot <путь> --admin --width 1200 --full`,
  файлы в `apps/web/.screenshots/`. Что снимком не поймать — окно, фокус,
  перетаскивание — проверяется одноразовым сценарием Playwright из
  контейнера: `npx tsx <файл>.mts` рядом с `apps/web`, вход берётся из
  `e2e/support/admin-ui`, контексту нужен `baseURL: BASE_URL`.
- 🔴 **`next build` и дев-сервер делят том `.next`, и это ломает обоих.**
  Сборка при живом сервере падает на пререндере 404 с невнятным «Cannot find
  module for page: /_document». Собирать одноразовым контейнером:
  `docker compose -f docker-compose.dev.yml run --rm --no-deps -e SITE_URL=https://build.invalid web sh -c "cd /app/apps/web && pnpm build"`.

  🔴 **Вторая половина, без которой первая бесполезна: после любой боевой
  сборки стенд нужно восстановить.** Сборка затирает дев-артефакты, и сайт
  начинает отдавать HTML со ссылками на несуществующие стили — страница
  открывается голой, статус 200, в логах пусто, а CSS-файлы дают 404. Симптом
  выглядит как «сломали вёрстку», хотя код цел.

  ```
  docker compose -f docker-compose.dev.yml exec -T web sh -c "cd /app/apps/web && rm -rf .next/*"
  docker compose -f docker-compose.dev.yml restart web
  ```

  Снаружи том занят (`Resource busy`) — чистить только изнутри контейнера.
  Проверять не глазами на одной странице, а отдачей самих файлов:
  `curl -s http://localhost:3000/catalog | grep -o '/_next/static/css/[^"?]*' | sort -u` и каждый адрес curl'ом — они обязаны давать 200, а не 404.

- 🔴 **Новый слот `@modal` в существующем разделе не подхватывается Fast
  Refresh.** До `docker compose -f docker-compose.dev.yml restart web` клик
  уходит обычным переходом: 200 и страница вместо окна — ровно тот ложный
  диагноз «сломанный перехватывающий маршрут», что и ниже. Перезапустите
  контейнер, прежде чем искать ошибку в маршрутах.
- 🔴 **`router.refresh()` рядом с закрытием окна не работает.** «Назад» — это
  переход, и запрос, начатый до него, роутер отбрасывает: запись заводилась, а
  списка под окном она не меняла. Обновление просится у самого закрытия —
  `close({ refresh: true })` из `useRouteClose`; своего обхода в разделе быть
  не должно.
- 🔴 **Признак `dirty` снимается `onChange`, а не `onInput`.** У `<select>`
  React берёт `onChange` из нативного `change`, а `input` приходит раньше:
  пометка перерисовывает управляемый список, тот откатывается, и первый выбор
  пропадает молча. Ловится только браузером — в jsdom порядок событий другой.
- 🔴 **Клик в тесте браузера до гидратации уходит в обычный переход**, и
  модальное окно не рисуется: страница отвечает 200, окна нет, и выглядит
  это как сломанный перехватывающий маршрут. Перед кликом нужна пауза после
  `networkidle` — иначе диагноз будет ложным (проверено дважды).
- 🔴 **Свежая миграция не видна дев-серверу без перезапуска.** `next dev`
  держит в памяти клиент Prisma, сгенерированный до неё, и любой маршрут по
  новым таблицам падает с «Cannot read properties of undefined (reading
  \'findMany\')». Лечится `docker compose -f docker-compose.dev.yml restart web`
  — это не дефект кода, и искать его в репозитории бесполезно.
- **`prisma migrate dev` в контейнере не работает при предупреждении** (новый
  уникальный индекс, потеря колонки): команда интерактивна и падает с «non-
  interactive environment». Обход — сгенерировать SQL
  (`prisma migrate diff --from-schema-datasource --to-schema-datamodel
--script`) в папку миграции и применить `prisma migrate deploy`.

## Чего нет и почему

| Чего нет                             | Почему                                                                                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Эталонов снимков в репозитории       | Решено не хранить (ADR-230): эталон — кадры базы `merge-base`, снятые в той же работе CI; 3408 PNG весили половину `.git`                              |
| Запуска вне Docker                   | `pnpm install` на хосте отдаёт пустой `node_modules` (ADR-028)                                                                                         |
| Карты на контактах                   | Решение о встраивании отложено                                                                                                                         |
| Автодеплоя с пуша                    | Сознательно: на проекте одного разработчика рисков больше, чем экономии                                                                                |
| Отдельных посадочных страниц         | Сайт — лендинг (ADR-049). Каталог и страницы моделей вернулись отдельным решением (ADR-109); гео-страницы по районам — только с уникальным содержанием |
| Реестра образов                      | Сборка идёт на сервере; реестр — решение владельца, когда VPS станет мало                                                                              |
| Напоминаний о делах календаря        | Сначала нужен сам график: уведомлять о делах, которых никто не завёл, не о чем (ADR-080)                                                               |
