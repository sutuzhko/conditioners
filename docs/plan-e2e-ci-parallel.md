# Plan: Сквозные сценарии в CI: шлюз, кеш зелёного прогона, группы параллельно

**PRD:** [prd-e2e-ci-parallel.md](prd-e2e-ci-parallel.md)
**Дата:** 2026-09-03

## Фазы реализации

### Фаза 1: Четыре группы параллельно со сводным вердиктом

**Цель:** Сквозной минимум: сценарии идут четырьмя группами на своих раннерах,
`e2e` — сводный вердикт над ними с тем же именем; критический путь падает с
десяти минут до четырёх-пяти. Ни один spec-файл не может выпасть из CI молча.
**Затрагивает:** инфраструктура / тесты

**Задачи:**

- [ ] Состав групп в одном месте (`scripts/e2e-groups.mjs`): четыре группы
      spec-файлов, взвешенные по замеру; список файлов группы для раннера;
      проверка «каждый spec-файл ровно в одной группе» против каталога `e2e/`;
      тесты vitest — файл вне групп и файл в двух группах красят
- [ ] Шард `e2e-shard` матрицей групп: своя база, схема, оба сида, приложение;
      прогон файлов группы в дев-образе; итог группы из JSON-репортера
      Playwright и маркер исхода раннера — артефактом; трассы падений —
      артефактом на группу
- [ ] Сводка `scripts/e2e-summary.mjs`: читает итоги групп; красит при неполном
      наборе, при упавшем раннере, при упавших сценариях и при группе без
      единого пройденного теста; flaky — предупреждение; таблица по группам в
      `$GITHUB_STEP_SUMMARY`; тесты vitest на каждую причину красного и зелёного
- [ ] Сводная работа `e2e` над шардами: `if: !cancelled()`, флаг раннера,
      проверка состава групп, сторож «Вердикт работы»; замер критического пути
      до и после — в описании PR
- [ ] ADR с решением, замером и отвергнутыми вариантами; ROADMAP и HANDOFF
      описывают новый порядок

**Проверка:** PR с правкой исходников — четыре группы параллельно, `e2e`
зелёная, в сводке таблица по группам; нарочно сломанный сценарий — `e2e`
красная с именем группы и файла, трассы группы артефактом; spec-файл вне групп
— красные `pnpm test` и сводка.

**Когда готова:** Критерии PRD 3–7 и 9 отмечены; критический путь `e2e` на PR
с правкой исходников не больше 5 минут; защита `main` не переписывалась.

### Фаза 2: Шлюз по изменённым файлам и кеш зелёного прогона

**Цель:** Сценарии не запускаются там, где правка не могла изменить их исход, и
не повторяются для кода, который уже прошёл: PR с документацией и повторный
запуск ярлыком заканчиваются за секунды.
**Затрагивает:** инфраструктура / тесты

**Задачи:**

- [ ] Перечень путей в одном месте (`scripts/e2e-scope.mjs`): решение по
      списку изменённых файлов и ключ содержимого из `git ls-tree` по тем же
      путям; тесты vitest — документация не задевает, исходники задевают,
      истории и юниты не задевают, ключ не меняется от нерелевантных путей и
      меняется от релевантных
- [ ] Шлюз в шарде и в сводке по образцу ADR-221: не PR — гоняем всё; список
      файлов PR через API; вне перечня — зелёная за секунды; сторож «шлюз не
      отработал — красная»
- [ ] Маркер зелёного прогона: сводка пишет его в кеш Actions под ключом
      содержимого только при зелёном вердикте; шард и сводка перед работой
      проверяют кеш без скачивания и при попадании завершаются зелёными,
      называя ключ и прогон-источник
- [ ] Документация: ADR дополнен следствиями шлюза и кеша; CLAUDE.md, HANDOFF
      и комментарии `ci.yml` описывают новый порядок

**Проверка:** PR только с документацией — `e2e` зелёная за секунды с причиной в
журнале; ярлык `vr:accepted` на PR с уже пройденным кодом — зелёная за секунды
с ключом и прогоном-источником в журнале; правка `src/` — полный прогон групп.

**Когда готова:** Критерии PRD 1, 2, 8 и 10 отмечены.
