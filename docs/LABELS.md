# Ярлыки задач — четыре оси

> Словарь — [`scripts/labels.mjs`](../scripts/labels.mjs), он же источник
> правды. Здесь — что означает каждая ось и как выбирать между похожими
> ярлыками.
>
> Решение и отвергнутые варианты: [DECISIONS.md](DECISIONS.md), ADR-330.
> Требования: [prd-issue-labels-taxonomy.md](prd-issue-labels-taxonomy.md).

---

## Зачем оси

До 7 сентября ярлыки лежали на одной плоской оси и смешивали «что делаем» с
«чем это пахнет технически». Самый частый из них, `ui`, стоял на 29 задачах
из 88 — и на публичной части, и в панели, то есть ровно там, где различие
нужно, его не было. Восемь задач не имели ярлыков вообще.

Разметка по осям отвечает на разные вопросы разными ярлыками, и по строке
видно, чего задача касается, не открывая её.

| Ось        | Вопрос                    | Сколько на задаче | Цвет       |
| ---------- | ------------------------- | ----------------- | ---------- |
| `area/`    | Где в продукте            | 🔴 ровно одна     | синий      |
| `module/`  | Что именно затронуто      | ноль или больше   | зелёный    |
| `kind/`    | Что делаем                | 🔴 ровно один     | оранжевый  |
| `quality/` | Какое сквозное требование | ноль или больше   | фиолетовый |

🔴 **Имена по-английски, описания по-русски.** `label:module/stock` — это
адрес, и на него распространяется инвариант 17 наравне с маршрутами и
якорями; кириллица вдобавок требует кавычек в `gh`. Описание читает человек,
и оно остаётся русским.

Цвет один на ось не для красоты: GitHub рисует ярлыки строкой и про оси не
знает, так что группирует их только цвет.

🔴 **Правило «ровно одна» — про задачу, а не про Pull Request.** Ветка
законно трогает несколько частей разом: первый же PR разметки получил
`area/infra`, `area/process` и `area/docs`, потому что тронул
`scripts/`, скилл и журналы. На PR ярлыки описывают состав правки, ревизор
туда не смотрит.

🔴 **GitHub не умеет «ровно одна `area/`».** Он не помешает поставить две
или ни одной — это держится ревизором `checkAxes`, а не настройкой
репозитория.

## Ось `area/` — где в продукте

| Ярлык          | Что покрывает                                                 |
| -------------- | ------------------------------------------------------------- |
| `area/site`    | публичные страницы: лендинг, каталог, статьи, отзывы, формы   |
| `area/panel`   | админка: разделы, оболочка, формы и таблицы                   |
| `area/api`     | маршруты, сервисы, доступ к данным, схема БД                  |
| `area/infra`   | CI, Docker, сборка, бюджеты, сквозные проверки, наблюдаемость |
| `area/process` | маршрут задачи: ветки, Pull Request, стенды, хуки, скиллы     |
| `area/shared`  | код, служащий сразу сайту и панели: кит, токены, сущности     |
| `area/docs`    | ADR, журналы, PRD и планы, PIXEL_SPEC                         |

**`infra` или `process`?** Инфраструктура — то, что исполняет машина:
пайплайн, образ, скрипт замера. Процесс — то, чему следует человек или
агент: как заводится ветка, что обязано быть в Pull Request, что делает
скилл. Починка `vr:measure:pull` — инфра. Правило «после merge догнать
main» — процесс.

**`shared` или `panel`?** По тому, где лежит правка, а не чем она
пользуется. Правка компонента в `shared/ui` — `shared`, даже если поводом был
один экран панели. Замена поля в девяти формах панели на готовый компонент
кита — `panel`: кит при этом не меняется.

**`api` или `panel`?** Экран — панель, маршрут — api. Задача, которая
делает и то и другое, берёт часть по тому, где основная работа; если
поровну — по тому, что сломано у владельца.

## Ось `module/` — что именно затронуто

Разделов у задачи может быть больше одного, и это норма, а не ошибка:
расход материалов в наряде — это и `orders`, и `stock`.

| Ярлык                  | Путь в коде                                                                 |
| ---------------------- | --------------------------------------------------------------------------- |
| `module/catalog`       | `(site)/catalog`, `(panel)/catalog`, `api/admin/models`, `entities/product` |
| `module/specs`         | `(panel)/catalog/specs`, `features/specs-dictionary`                        |
| `module/prices`        | `(panel)/prices`, `api/prices`, `entities/price`, `widgets/pricing`         |
| `module/discounts`     | `features/product-sale`, `api/admin/models/*/sale`                          |
| `module/leads`         | `api/leads`, `(panel)/leads`, `features/lead-form`, `lead-manager`          |
| `module/clients`       | `(panel)/clients`, `api/admin/clients`, `entities/client`                   |
| `module/orders`        | `(panel)/orders`, `api/admin/orders`, `entities/order`                      |
| `module/calendar`      | `(panel)/crm`, `api/admin/crm`, `features/crm-calendar`                     |
| `module/stock`         | `(panel)/stock`, `api/admin/stock`, `entities/stock`                        |
| `module/team`          | `(panel)/team`, `api/admin/staff`, `entities/staff`                         |
| `module/reviews`       | `api/reviews`, `(panel)/reviews`, `features/review-*`                       |
| `module/knowledge`     | `(site)/knowledge`, `(panel)/knowledge`, `api/admin/articles`               |
| `module/settings`      | `(panel)/settings`, `(panel)/company`, `api/settings`                       |
| `module/notifications` | `server/notifications`, `api/telegram`, `features/delivery-log`             |
| `module/auth`          | `admin/login`, `api/auth`, `(panel)/profile`, `server/auth.ts`              |
| `module/landing`       | `widgets/hero`, `honesty`, `trust`, `faq`, `installation`, `service`        |
| `module/compare`       | `(site)/compare`                                                            |
| `module/kit`           | `shared/ui`, `shared/styles`, `.storybook`                                  |
| `module/media`         | `api/media`, `public/`                                                      |
| `module/weather`       | `api/weather`, `features/weather-chip`                                      |

**`site` или `landing`?** `area/site` стоит на всей публичной части;
`module/landing` — только на коммерческих секциях главной. Правка карточки
каталога — `area/site · module/catalog`, лендинга там нет.

🔴 **Пути — не украшение.** Из них генерируется карта для `actions/labeler`,
и тест сверяет каждый путь с настоящим деревом: путь, ведущий в
несуществующий каталог, перестал бы ставить ярлык молча.

## Ось `kind/` — что делаем

| Ярлык               | Когда                                                  |
| ------------------- | ------------------------------------------------------ |
| `kind/bug`          | работает не так, как задумано                          |
| `kind/enhancement`  | новая возможность или развитие существующей            |
| `kind/audit`        | найдено ревью или проверкой, журнал [BUGS.md](BUGS.md) |
| `kind/refactor`     | внутреннее устройство без изменения поведения          |
| `kind/verification` | приёмка фазы: тесты, замеры, снимки, сквозные сценарии |
| `kind/decision`     | требует решения владельца и записи ADR                 |

**`bug` или `audit`?** Дефект видно снаружи: владелец нажал и получил не
то. Аудит нашла проверка — контраст 3.9:1, цель 39.9px, — и снаружи он ещё
никого не задел. Разница в том, кто платит за отсрочку.

**`refactor` или `quality/`?** Рефакторинг меняет устройство и не меняет
поведение. Ось `quality/` — требование, по которому работу принимают; она
ставится вместе с типом, а не вместо него.

🔴 **Ось `kind/` — ярлыки, а не нативное поле issue types**, потому что типы
задач — функция организации, а репозиторий пока личный. При переносе ось
конвертируется в типы один в один: переразметки не потребуется.

## Ось `quality/` — сквозное требование

Идёт поперёк разделов. Это **не «плохой код»** — для него есть
`kind/refactor`. Это нефункциональные требования, по которым считают долг
и принимают работу.

| Ярлык                | Что стоит за ним                              |
| -------------------- | --------------------------------------------- |
| `quality/a11y`       | клавиатура, фокус, роли и имена, контраст AA  |
| `quality/perf`       | Core Web Vitals, бюджет JS, число запросов    |
| `quality/security`   | секреты, права, ограничение частоты, загрузки |
| `quality/seo`        | каноникал, метаданные, JSON-LD, sitemap       |
| `quality/responsive` | поведение раскладки между 320 и 1440          |
| `quality/dark-theme` | вторая тема: палитра, контраст, снимки        |
| `quality/privacy`    | персональные данные и 152-ФЗ (инвариант 12)   |

Смысл оси — в вопросе «где у нас копится долг по доступности», на который
раньше отвечать было нечем: `accessibility` стоял на двух задачах из восьми,
которые про доступность.

## Служебные ярлыки

Вне осей: они описывают не задачу, а её состояние или машинный шлюз.

| Ярлык         | Что делает                                                       |
| ------------- | ---------------------------------------------------------------- |
| `vr:accepted` | 🔴 автор принял расхождение снимков, проверка зеленеет (ADR-230) |
| `blocked`     | ждёт другой задачи или решения владельца                         |
| `duplicate`   | повторяет уже заведённую задачу                                  |
| `wontfix`     | решено не делать                                                 |

🔴 **`vr:accepted` переименованию не подлежит.** Его имя читает CI —
`.github/workflows/ci.yml`, строки 609 и 1111. Тест сверяет словарь с этим
файлом, чтобы переименование не прошло тихо.

## Как добавить или изменить ярлык

1. Правка [`scripts/labels.mjs`](../scripts/labels.mjs) в ветке, Pull Request.
2. После merge — `node scripts/labels-sync.mjs --apply`.

```
node scripts/labels-sync.mjs                 # что изменится, ничего не делая
node scripts/labels-sync.mjs --apply         # завести и поправить
node scripts/labels-sync.mjs --apply --prune # ещё и удалить лишние
```

🔴 **Удаление отделено флагом `--prune` намеренно.** Ярлык, снятый с 88
задач, обратно не возвращается: GitHub не хранит историю снятой разметки, и
восстанавливать пришлось бы руками по памяти.

## Чего в ярлыках нет

- **Статуса** («в работе», «на ревью») — это поле проекта. Два источника
  правды о состоянии задачи разъезжаются в первую же неделю.
- **Приоритета** — его роль играют вехи: задача либо в фазе, либо нет.
- **Фазы** — веха и есть фаза.
