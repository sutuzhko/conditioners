# Plan: Хвосты календаря — поиск, горячие клавиши, многодневные отлучки, перенос перетаскиванием

**PRD:** [prd-calendar-tails.md](prd-calendar-tails.md)
**Дата:** 2026-08-29

## Фазы реализации

### Фаза 1: Клавиатура водит по календарю

**Цель:** Календарь переключается видами и периодами без мыши. Минимальный
рабочий путь: правка целиком на клиенте, ни схемы, ни маршрутов не трогает,
результат виден в первый же день.
**Затрагивает:** frontend

**Задачи:**

- [ ] Завести клавиши на виды «день», «неделя», «месяц» и на «сегодня»
- [ ] Завести переход по периодам назад и вперёд стрелками
- [ ] Не перехватывать клавиши при вводе текста — в поле поиска и в формах
      буквы остаются буквами
- [ ] Показать подсказку по клавишам из шапки календаря
- [ ] Тесты поведения на клавиатуру и просмотр через Playwright MCP на 375,
      768 и 1280 в обеих темах

**Когда готова:** Виды, «сегодня» и переходы по периодам работают с
клавиатуры; в поле ввода клавиши не срабатывают; подсказка открывается из
шапки.

### Фаза 2: Сервер умеет искать по календарю

**Цель:** Появляется маршрут поиска, отдающий совпадения по делам, нарядам и
заявкам с учётом роли смотрящего. Экрана ещё нет — проверяется ответом API.
**Затрагивает:** backend

**Задачи:**

- [ ] Завести поиск по названию, клиенту и адресу среди дел, нарядов и
      заявок, не ограниченный видимым периодом
- [ ] Фильтровать выдачу по роли: монтажник получает только своё
- [ ] Описать маршрут в [API.md](API.md) тем же коммитом
- [ ] Интеграционные тесты: находка вне видимого периода; монтажник не
      получает ни одной чужой записи

**Когда готова:** Маршрут отдаёт совпадения по трём видам записей, роль
учтена, тесты зелёные.

### Фаза 3: Поиск на экране календаря

**Цель:** Владелец находит запись, не помня её даты, и попадает на её день.
**Затрагивает:** frontend

**Задачи:**

- [ ] Поставить поле поиска в шапку календаря
- [ ] Показать список совпадений с датой и видом записи
- [ ] Открывать день выбранной находки и подсвечивать саму запись во всех
      трёх видах
- [ ] Тест поведения на выбор находки клавиатурой и мышью, просмотр через
      Playwright MCP в обеих темах

**Когда готова:** Найденная запись открывается своим днём и подсвечена;
поиск доступен с клавиатуры.

### Фаза 4: Отлучка живёт диапазоном

**Цель:** Отпуск и больничный становятся одной записью, и занятость считает
весь их диапазон. Домен и база — без правок экранов.
**Затрагивает:** database / backend

**Задачи:**

- [ ] Свериться с [ADR-160](DECISIONS.md) — он уже отменяет часть ADR-140 по
      многодневным отлучкам и переносу вбок — и дописать в него решения по
      хранению диапазона, которых он не покрывает
- [ ] Добавить отлучке дату окончания — схема, миграция с приведением
      существующих строк, валидация диапазона
- [ ] Считать занятость по всему диапазону: слой занятости, пометка занятых
      при назначении наряда, проверка пересечений
- [ ] Тесты: отлучка на 14 дней делает монтажника занятым в каждый из них во
      всех трёх местах
- [ ] Прогон миграции на заполненной базе: у заведённых отлучек окончание
      равно началу, ни одна запись не потеряна

**Когда готова:** Отлучка хранит диапазон, занятость учитывает его
одинаково везде, миграция прошла на заполненной базе.

### Фаза 5: Отлучка видна полосой

**Цель:** Многодневная отлучка читается в календаре так же, как в эталоне:
полосой через дни, а не четырнадцатью отдельными записями.
**Затрагивает:** frontend

**Задачи:**

- [ ] Рисовать многодневную отлучку полосой «Весь день» через колонки в
      неделе и дне
- [ ] Рисовать её сплошной плашкой через нужные дни в месяце
- [ ] Дать форме отлучки дату окончания
- [ ] Снимки календаря на 375, 768 и 1280 в обеих темах и тест поведения
      формы

**Когда готова:** Отпуск на две недели заводится одной записью и тянется
через все дни во всех трёх видах.

### Фаза 6: Перенос перетаскиванием

**Цель:** Дело и отлучка переносятся на другой день движением мыши, а наряд
и заявка — по-прежнему только своим разделом.
**Затрагивает:** frontend

**Задачи:**

- [ ] Дать делу перетаскивание вбок: день меняется, время сохраняется
- [ ] Дать то же отлучке, с сохранением длительности диапазона
- [ ] Оставить наряд и заявку неперетаскиваемыми
- [ ] Сохранить клавиатурный путь: перенос через форму с явным выбором дня
- [ ] Тесты переноса и запрета для наряда и заявки, просмотр через Playwright
      MCP; замер бюджета JS после правки

**Когда готова:** Дело и отлучка переносятся вбок с сохранением времени,
наряд и заявка не двигаются, клавиатурный путь приводит к тому же
результату.
