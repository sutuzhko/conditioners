# Plan: Разметка задач по осям

**PRD:** [docs/prd-issue-labels-taxonomy.md](prd-issue-labels-taxonomy.md)
**Дата:** 2026-09-07

## Фазы реализации

### Фаза 1: Словарь есть в репозитории и применён к GitHub

**Цель:** Сквозной минимум — ярлык описан файлом, попадает на GitHub
скриптом и стоит на живой задаче. Дальше всё остальное только повторяет этот
путь на объёме.
**Затрагивает:** repo / GitHub
**Задачи:**

- [ ] Завести `scripts/labels.mjs` — четыре оси и служебные ярлыки, у
      каждого имя, описание и цвет своей оси
- [ ] Написать `scripts/labels-sync.mjs`: заводит недостающие, правит цвет и
      описание изменившихся, удаляет лишние только с явным флагом
- [ ] Написать `docs/LABELS.md` — что означает ось, где граница между
      похожими ярлыками, какому пути в коде отвечает каждый `раздел/`
- [ ] Применить словарь к репозиторию и разметить одну задачу целиком
      (#643 — `часть/инфра · раздел/кит · тип/дефект`) как образец
- [ ] Тесты: повторный запуск скрипта не меняет ничего (идемпотентность);
      запуск без флага удаления не трогает существующие ярлыки

**Когда готова:** `node scripts/labels-sync.mjs` дважды подряд — второй
запуск печатает «изменений нет»; на #643 стоят три новых ярлыка и ни одного
старого.

### Фаза 2: Открытый бэклог размечен

**Цель:** По списку задач видно, чего каждая касается. Это то, ради чего всё
затевалось.
**Затрагивает:** GitHub
**Задачи:**

- [ ] Собрать разметку 88 открытых задач файлом `номер → ярлыки` с пометкой
      спорных, вывести на вычитку владельцу
- [ ] Применить разметку батчем `gh issue edit` после вычитки
- [ ] Снять старые ярлыки со всех открытых задач и удалить их из
      репозитория, кроме `vr:accepted`
- [ ] Разнести восемь задач без ярлыков (#427, #429, #434, #657, #658, #670,
      #689, #690) и двадцать без вехи
- [ ] Проверка: скрипт-ревизор печатает задачи, у которых не ровно одна
      `часть/` или не ровно один `тип/`; список пуст

**Когда готова:** ревизор молчит на всех 88 открытых задачах; `gh label list`
не содержит `ui`, `data`, `infra`, `process`, `calendar`, `design`, `test`,
`audit`, `bug`, `enhancement`, `security`, `accessibility`, `documentation`.

### Фаза 3: Ярлык ставит машина, а не память

**Цель:** Разметка перестаёт зависеть от того, вспомнил ли агент про
словарь. Без этой фазы всё расползётся заново за месяц — восемь задач без
ярлыков появились ровно так.
**Затрагивает:** CI / repo
**Задачи:**

- [ ] Завести `.github/labeler.yml` — карта «путь → `раздел/`» и
      «путь → `часть/`» по маршрутам приложения
- [ ] Подключить `actions/labeler` на событие Pull Request
- [ ] Написать workflow-ревизор осей на `issues: opened, labeled,
unlabeled` — комментирует нарушение осей
- [ ] Научить скилл `issues` словарю: ярлыки только из `scripts/labels.mjs`,
      обязательные оси — обязательны
- [ ] Тесты: PR, тронувший `stock/`, получает `раздел/склад`; issue без
      `часть/` получает комментарий; issue с двумя `тип/` тоже

**Когда готова:** на живом PR ярлык раздела появился сам; issue, заведённая
без `часть/`, получила комментарий.

### Фаза 4: Витрина — таблица со срезом и виды

**Цель:** Бэклог читается одним экраном, а не поиском по строке фильтра.
**Затрагивает:** GitHub
**Задачи:**

- [ ] Обновить токен `gh` скоупом `project` и завести проект «Бэклог
      ТулаКлимат»
- [ ] Добавить все открытые задачи в проект, настроить таблицу со срезом по
      `раздел/` и группировкой по `часть/`
- [ ] Завести пять-шесть сохранённых видов: «Панель», «Публичная часть»,
      «Дефекты», «Долг по доступности», «Без разбора»
- [ ] Дописать в [CLAUDE.md](CLAUDE.md) раздел про оси разметки и ссылку на
      [LABELS.md](LABELS.md)
- [ ] Записать ADR: оси, границы, что отвергнуто (issue types до переноса в
      организацию, приоритет ярлыком, статус ярлыком)

**Когда готова:** проект открывается таблицей со срезом по разделам, у
каждого раздела счётчик; ADR в [DECISIONS.md](DECISIONS.md).
