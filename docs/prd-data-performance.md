# PRD: Доработки после аудита — данные, контракт и производительность

**Дата**: 2026-08-29
**Статус**: Draft

## Цель

Закрыть двадцать открытых дефектов доменных правил, контракта API и
производительности из [BUGS.md](BUGS.md): заявка не теряется при отказе
сервера, цена и скидка не врут, `PATCH` не стирает непереданные поля, а
публичные страницы укладываются в бюджеты Core Web Vitals. Здесь же — защита
от того, что двое в панели молча затирают правки друг друга.

## Пользовательские сценарии

- Менеджер меняет статус заявки, сервер отказывает → на экране прежний статус,
  а не расхождение с базой
- Посетитель видит скидку в сто рублей → плашки «−0%» нет ни на одной витрине
- Владелец сохраняет прайс со строкой без класса → видит, какая строка не
  прошла, и не теряет введённое
- Владелец правит склад, не прислав `minQty` → порог заказа остаётся прежним,
  а не обнуляется
- Владелец назначает монтажника на наряд → статус становится «Назначен» сам
- Двое в панели правят один наряд → второй получает предупреждение, а не
  затирает правку первого молча
- Посетитель нажимает фильтр в каталоге → видит скелетон, а не замерший экран
- Посетитель открывает главную с телефона → HTML не тащит весь каталог с
  фотографиями, бюджет JS не превышен
- Владелец смотрит источники заявок → атрибуция собрана сервером из
  заголовков, как обещает [API §8](API.md), и её нельзя подменить телом
  запроса
- Монтажник отменяет списание при обрыве связи → видит настоящую ошибку, а не
  «уже отменено»

## В скоупе

Доменные правила и контракт:

- **P2 · Оптимистичный статус заявки не откатывается при отказе**
  ([BUGS §3017](BUGS.md)); тот же класс — чеклист выезда
- **P2 · Скидка в сто рублей рисуется плашкой «−0%»**
  ([BUGS §3044](BUGS.md)) — `getActivePrice` и три потребителя
- **P2 · Форма прайса молча теряет строку** ([BUGS §3058](BUGS.md)) — нет
  клиентской проверки, отказ сервера без разбора `field`
- **P2 · Две фичи не отличают истёкшую сессию от отказа сервера**
  ([BUGS §3075](BUGS.md)) — `profile-form` и `specs-dictionary` мимо
  `adminRequest`, с запрещённым приведением типа
- **P2 · Происхождение заявки принимается от кого угодно, вопреки контракту**
  ([BUGS §3167](BUGS.md))
- **P2 · `cancelConsumption` выдаёт любую ошибку базы за «уже отменено»**
  ([BUGS §3213](BUGS.md))
- **P2 · `fromLead`: транзакция не защищает от гонки** ([BUGS §3224](BUGS.md))
- **P2 · Наряд с назначенным монтажником остаётся в статусе «Новый»**
  ([BUGS §3656](BUGS.md))
- **P2 · `PATCH` склада работает как полная замена** ([BUGS §3686](BUGS.md)) —
  пропущенное поле сбрасывает порог заказа и возвращает позицию из архива
- **P3 · Домен: краевые случаи и мёртвый код — пачка**
  ([BUGS §3291](BUGS.md)) — `basePriceForClass` без потребителя,
  перевёрнутый период скидки и скидочная цена выше обычной на сервере
- **P3 · Доменные схемы: остаток пачки** ([BUGS §3716](BUGS.md)) — `leadId`
  без проверки, `P2003` превращается в 500
- **P3 · Гигиена слоя данных — остаток пачки** ([BUGS §321](BUGS.md)) —
  `Notification.channel`/`kind` строками там, где нужен enum

Параллельная работа:

- **P2 · Двое в панели: сохранение затирает правку коллеги молча**
  ([BUGS §1864](BUGS.md)) — `PATCH` со всеми полями сразу, сервер принимает
  любой набор
- **P3 · Реалтайм в панели** ([BUGS §1896](BUGS.md)) — намерение владельца,
  нужно решение и ADR: нужен ли, в каком объёме, какой ценой

Производительность:

- **P2 · Настройки читаются из базы три-четыре раза на каждый рендер**
  ([BUGS §3096](BUGS.md))
- **P2 · Весь каталог с фотографиями уезжает в HTML первого экрана**
  ([BUGS §3114](BUGS.md)) — 95% полезной нагрузки лишние
- **P2 · Карточка наряда открывается одиннадцатью клиентскими запросами**
  ([BUGS §3136](BUGS.md))
- **P2 · На публичных маршрутах нет ни одного скелетона перехода**
  ([BUGS §3151](BUGS.md)) — `loading.tsx` в `(site)` ноль, скелетоны написаны
  и не используются
- **P2 · Бочонок `shared/ui` тянет весь кит в чанк лендинга**
  ([BUGS §1286](BUGS.md)) — бюджет собственного JS занят на 74,7 из 75 КБ
- **P3 · `/api/media` отдаёт первый запрос почти три секунды**
  ([BUGS §2346](BUGS.md)) — и `sizes` у аватаров тянет вариант `w=256`

## Не в скоупе

- Вёрстка, состояния и доступность экранов —
  [prd-ui-accessibility.md](prd-ui-accessibility.md)
- Доступ по ролям и защита маршрутов —
  [prd-security-access.md](prd-security-access.md)
- Сам переезд бэкенда на NestJS — намерение владельца, решение отложено,
  первый модуль начинается с нового ADR
- Смена версии Next ради платформенного пола бюджета JS (105 КБ) — не наш код
- Пагинация листинга статей — при нынешних объёмах не нужна, компонент готов

## Технические ограничения

- **Обработчик маршрута — контроллер** (ADR-142): порядок записей, транзакции
  и компенсация живут в `server/services/`, слой заводится по надобности
- **Контракт [API.md](API.md) соблюдается буквально** — правка поведения либо
  приводит код к контракту, либо меняет контракт тем же коммитом
- **Инвариант 2**: заявка сначала в БД, уведомление потом; ответ `201` не
  зависит от Telegram и SMTP
- **Инвариант 1**: публичные страницы приходят с сервера с данными; разгрузка
  HTML не должна превратить каталог в клиентскую сборку
- **Инвариант 14 и ADR-011**: перечёркнутая цена — только реально
  действовавшая; исправление «−0%» не должно скрыть настоящую скидку
- **Бюджет**: LCP < 2.0 с, CLS < 0.05, INP < 200 мс, собственный JS < 75 КБ на
  самой тяжёлой публичной странице; проверка — `node scripts/js-budget.mjs`
  после боевой сборки, замер до и после правки
- **Боевая сборка затирает `.next`** и ломает стенд — замер бюджета
  планируется отдельным окном, а не между делом
- **Миграция для enum `Notification.channel`** требует приведения типов на
  существующих строках; только через `prisma migrate`
- **TDD обязателен**: цены, скидки, калькулятор, запись заявки

## Критерии готовности

- [ ] Юнит-тесты: `getActivePrice` не отдаёт `discountPercent: 0` при
      `saleActive: true` ни на одной комбинации цен; перевёрнутый период и
      скидочная цена выше обычной отклоняются схемой на сервере
- [ ] Юнит-тесты схем: `PATCH` склада с одним полем не меняет остальные;
      наряд с `installerId` не остаётся в статусе «Новый»; `leadId`
      проверяется наравне с `clientId` и `installerId`
- [ ] Интеграционный тест: `sourceUrl`, `referrer` и utm из тела запроса
      игнорируются, значения собраны из заголовков — поведение совпадает с
      [API §8](API.md), старый тест переписан
- [ ] Интеграционный тест: отмена списания при ошибке базы, не связанной с
      повтором, отдаёт настоящую ошибку, а не «уже отменено»
- [ ] Интеграционный тест: два одновременных обращения с одного номера дают
      одного клиента и ни одной пятисотки
- [ ] Отказ сервера при смене статуса заявки возвращает прежнее значение на
      экране — покрыто тестом компонента
- [ ] Ошибка в строке прайса показывается у своей строки; строка без класса
      не исчезает молча
- [ ] Истёкшая сессия в профиле и справочнике характеристик даёт «войдите
      заново», а не «сервер не принял изменения»; приведения типов в этих
      файлах не осталось
- [ ] Одновременная правка одного наряда двумя людьми не затирает чужие поля
      молча — сценарий покрыт тестом, решение записано ADR
- [ ] Настройки читаются из базы один раз на запрос — замер числом запросов
      Prisma на `/`, `/catalog`, `/compare`, `/knowledge`
- [ ] Вес HTML главной уменьшился — замер до и после в задаче; в flight-данных
      нет фотографий и характеристик, не используемых первым экраном
- [ ] Карточка наряда открывается без клиентского веера запросов — начальные
      данные расхода приходят с сервером
- [ ] У каталога, сравнения и листинга статей есть `loading.tsx`; переход по
      фильтру показывает скелетон
- [ ] `node scripts/js-budget.mjs apps/web/.next --strict` проходит с запасом
      не меньше 5 КБ; замер приложен к задаче
- [ ] Первый запрос `/api/media` укладывается в 300 мс; на 375 через шесть
      секунд после `load` незагруженных изображений нет
- [ ] `pnpm check` в контейнере зелёный до и после каждой фазы; закрытые
      пункты отмечены в [BUGS.md](BUGS.md), решения — в
      [DECISIONS.md](DECISIONS.md)
