# PRD: Резиновая вёрстка публичной части

**Дата**: 2026-08-29
**Статус**: Draft
**Родитель**: issue [#179](https://github.com/) — шаг 4 «Перевёрстка» (ADR-170)
**Макет**: канвас «Главная ТулаКлимат · мобильная» — https://claude.ai/code/artifact/610ba28e-77fd-42fd-9046-960f3acba4d9
**Исходники макета**: `design/mobile-home/` (в репозитории, ADR-185)

---

## Цель

Публичная часть должна оставаться аккуратной и читаемой на любой ширине от 320
до 1440+, а не только на четырёх, которые кто-то однажды проверил. Сейчас
между брейкпоинтами раскладка прыгает, а на телефоне четыре узла обрезаются
краем экрана — и это те самые экраны, с которых приходит основная часть
трафика в нише «кондиционеры + город».

## Пользовательские сценарии

- Человек открывает сайт с телефона 375px → видит оффер, подбор по площади и
  кнопку заявки без горизонтальной прокрутки и без обрезанного текста
- Человек поворачивает телефон боком (640–740px) → раскладка плавно тянется, а
  не показывает мобильный вариант, растянутый на всю ширину
- Человек открывает сайт на планшете 820px → каталог идёт в две колонки,
  таблица цен читается, никакой блок не «зависает» на половине ширины
- Человек прокручивает длинную страницу с телефона → телефон и кнопка заявки
  остаются доступны, не перекрывая содержимое
- Человек с включённой тёмной темой проходит те же сценарии → контраст держит
  AA на всех ширинах
- Человек листает страницу пальцем → ни один интерактивный элемент не меньше
  44×44px, ни одна лента не обрывается без признака продолжения

## В скоупе

**Страницы** — вся публичная часть:

| Маршрут             | Что на нём                             |
| ------------------- | -------------------------------------- |
| `/`                 | лендинг, 17 блоков                     |
| `/catalog`          | листинг с фильтрами                    |
| `/catalog/[slug]`   | страница модели                        |
| `/compare`          | таблица сравнения                      |
| `/knowledge`        | листинг статей                         |
| `/knowledge/[slug]` | статья                                 |
| `/privacy`          | политика обработки персональных данных |
| `not-found` (404)   | страница несуществующего адреса        |
| `error` (500)       | страница ошибки                        |

**Работа**:

1. **Единый набор брейкпоинтов.** Сейчас в `apps/web/src` 107 медиа-запросов
   по ширине на 17 разных порогов: 359, 399, 480, 520, 560, 599, 600, 620,
   700, 720, 760, 899, 900, 999, 1000, 1040, 1100. DESIGN_BRIEF §6 объявляет
   четыре. Порогов остаётся четыре, они живут в одном месте, остальные уходят.
2. **Текучая шкала в токенах.** Кегли, вертикальный ритм секций, боковые поля
   и внутренние отступы карточек переводятся на `clamp()`: между брейкпоинтами
   макет тянется, а не стоит на месте и не прыгает ступенькой.
3. **Перевёрстка блоков** публичной части под эту шкалу и под макет: шапка,
   меню, липкая панель действий, первый экран с подбором, каталог, сравнение,
   цены с калькулятором, монтаж, сервис, отзывы, заявка, база знаний, вопросы,
   контакты, подвал.
4. **Починка четырёх обрезок**, найденных замером 29 августа: кнопка
   «+ Сравнить» в карточке каталога, описания в таймлайне «День монтажа»,
   лента симптомов в сервисе, лента отзывов.
5. **Доступность на всех ширинах**: тап-зоны от 44×44px, контраст AA в обеих
   темах, видимый фокус, порядок обхода с клавиатуры не зависит от ширины.
6. **Сеть проверок**: снимки историй на 320, 375, 768, 1200 в обеих темах и
   машинная проверка отсутствия горизонтального переполнения.

## Не в скоупе

- **Админка.** У неё своя, более плотная пластика (DESIGN_BRIEF §9) и своя
  задача под перевёрстку — issue #177. Кит `shared/ui` общий, поэтому правки
  геометрии кита согласуются с #178, но экраны панели здесь не трогаются.
- **Страница календаря работ.** Единственное исключение из эталона HeroUI
  (ADR-170), у неё свой эталон — Apple Calendar.
- **Палитра.** Светлая тема приведена к 4,5:1 по двум токенам в 535 местах;
  цвета не меняются. С эталона берётся геометрия и порядок, не палитра.
- **Содержательная композиция лендинга** — оффер, блоки доверия, порядок
  секций. Это продающая логика из PROJECT.md, а не задача вёрстки.
- **Новая функциональность.** Ни одного нового блока, ни одного нового поля.
  Исключение — липкая панель действий на телефоне: это не новая функция, а
  перенос уже существующих кнопки заявки и телефона из шапки.
- **Контент из базы.** Тексты, цены, модели и отзывы не правятся.
- **Переезд на HeroUI как на библиотеку.** Отложен до отдельного ADR (ADR-169).

## Технические ограничения

- 🔴 **Инвариант 1**: страницы остаются серверными. Ни один брейкпоинт не
  реализуется через определение ширины в JavaScript — только CSS.
- 🔴 **Инвариант 13**: изображения через `next/image` с заданными
  `width`/`height`; текучая ширина не отменяет резерв места под картинку.
- 🔴 **Бюджет собственного JS — 75 КБ, занято 74,7** (ADR-088). Резинность
  делается CSS-ом; на липкую панель действий и раскрывающиеся блоки бюджета
  почти нет. Проверка: `node scripts/js-budget.mjs apps/web/.next --strict`.
- 🔴 **Бюджеты Core Web Vitals** — часть определения «готово»: LCP < 2.0с,
  CLS < 0.05, INP < 200мс, Lighthouse mobile ≥ 90. Текучие кегли не должны
  давать сдвига макета при загрузке шрифта.
- **128 историй Storybook со снимками на четырёх ширинах.** Правка кита или
  токенов роняет снимки пачкой; эталоны пересчитываются осознанно, а не
  «обновить всё» (issue #238).
- **66 CSS-модулей** в публичной части — перевёрстка идёт блоками, не разом.
- 🔴 **`tsc` и тесты — только в контейнере** (ADR-147):
  `docker compose -f docker-compose.dev.yml exec -T web pnpm check`.
- **Только CSS-переменные в модулях**, ни одного хардкоженного цвета; глубина
  вложенности селекторов не больше двух, `!important` запрещён.
- **Смежные issue**: #182 (карточки товаров разъехались) закрывается работой
  по каталогу; #178 (геометрия кита по HeroUI) идёт параллельно и задевает те
  же файлы — порядок правок согласуется, чтобы не спорить в одних модулях.

## Критерии готовности

- [ ] `document.documentElement.scrollWidth` равен ширине окна на 320, 360,
      375, 390, 414, 480, 540, 600, 768, 820, 900, 1024, 1200, 1440 — на всех
      девяти публичных маршрутах, включая 404 и 500, в обеих темах
- [ ] В `apps/web/src` не осталось медиа-запросов по ширине с порогами вне
      объявленного набора; проверяется скриптом в CI
- [ ] Ни один блок публичной части не меняет раскладку скачком внутри
      интервала между брейкпоинтами: кегль заголовка, боковое поле и
      вертикальный ритм секции — непрерывные функции ширины
- [ ] Ни один текстовый узел не обрезан краем контейнера: у каждой ленты есть
      поля и затухание, у каждого обрыва текста — многоточие по слову
- [ ] Каждый интерактивный элемент — не меньше 44×44px на устройствах с
      грубым указателем; замер снимается в браузере, а не на глаз
- [ ] Контраст AA (4,5:1 для текста, 3:1 для границ) на всех перечисленных
      ширинах в обеих темах; прогон `shared/styles/contrast.test.ts` зелёный
- [ ] Высота главной на 375 не превышает 14 000px (было 21 769)
- [ ] Снимки историй пересняты и зелёные на 320, 375, 768, 1200 в обеих темах
- [ ] `node scripts/js-budget.mjs apps/web/.next --strict` проходит
- [ ] Lighthouse mobile ≥ 90 на главной и на странице модели
- [ ] `docker compose -f docker-compose.dev.yml exec -T web pnpm check` зелёный
- [ ] DESIGN_BRIEF §4 и §6 обновлены: набор брейкпоинтов, текучая шкала и
      правила лент записаны числами
