# BUGS.md

> Журнал замечаний и незакрытых задач. Заведён, чтобы найденное не терялось в переписке — контекст сессии не переживает сессию.

Статусы: `🔴` открыт · `🟡` в работе · `✅` закрыт
Приоритеты: `P1` ломает заявки, оплату или индексацию · `P2` заметно мешает · `P3` косметика

## Открытые — вёрстка и содержание

### 🔴 P2 · Погоды в Туле нет в первом экране

В макете рядом с заголовком чип с текущей и пиковой температурой. При переносе блок сознательно выброшен: это внешний запрос к open-meteo на критическом пути LCP (PIXEL_SPEC, отступление №7). Заказчик хочет его вернуть — значит нужен вариант без ущерба первому экрану: серверный запрос с кэшем на час, а не запрос из браузера при загрузке.

### 🔴 P2 · Калькулятор монтажа горизонтальный, нужен в две колонки

Сейчас поля идут в ряд, смета — снизу. Нужна раскладка «корзины»: слева параметры, справа смета с итогом и кнопкой. Причина не в красоте: при добавлении строк в смету блок сейчас прыгает по высоте.

### 🔴 P3 · Блок «Напомним про чистку» из макета не сделан

Тёмная панель в секции сервиса: телефон, выбор срока, отправка. Это ещё одна точка сбора заявки и ещё один канал уведомлений, то есть функциональность, а не вёрстка. Решение — делать или заносить в отступления — не принято.

### 🔴 P3 · Мелкие расхождения блока экономии с макетом

Кнопки режима крупнее макетных (кит `Button sm`: 40px, радиус 9px), у активной есть тень, которой в макете нет. Бегунки ползунков толще: кит рисует их вручную вместо `accent-color`. Подписи ползунков блок стилизует из своего модуля — лазейка мимо кита, просится проп размера у `RangeSlider`.

### 🔴 P3 · Ступени отступа карточки закрывают макет с погрешностью

В макете 26 / 30 / 32 / 34px, в ките `lg` = 28 и `xl` = 32. Расхождение до 2px. Дробить шкалу дальше — превратить её в набор произвольных чисел; решение отложено сознательно (ADR-039).

### 🔴 P3 · Подпись в замке логотипа: два источника противоречат

Прототип главной даёт 10.5px / 0.05em, файл логотипов — 11px / 0.06em. Нужен арбитраж.

## Открытые — инфраструктура

### 🔴 P1 · Нет браузеров для Playwright в образе

Снимки визуальной регрессии (ADR-021) запустить негде: Alpine официально Playwright не поддерживает. Нужен системный Chromium в дев-стадии либо отдельный образ. Без этого пиксель-перфект держится ровно до следующего коммита.

### 🔴 P2 · Порядок CSS-модулей в продовой сборке не проверен

Дефект с бургером на десктопе зависел от порядка файлов в бандле (ADR-038), а он может отличаться между дев-сборкой и продом. Проверено только в деве.

### 🔴 P3 · Две проверки готовности настроек

`entities/settings/lib/findSettingGaps` и `checkReadiness` + `REQUIRED_FIELDS` в репозитории. Смысл разный, но кандидат на сведение.

## Закрытые

### ✅ P1 · Двадцать тестов блока экономии удалены молча

При сведении блока с макетом агент удалил 20 тестов из 22, оставив осиротевшие помощники. Общее число тестов в проекте при этом росло за счёт других агентов, и падение осталось незаметным. Восстановлено из истории и адаптировано под текущую реализацию. **Урок: число тестов по проекту не показатель — покрытие нужно смотреть по файлу.**

### ✅ P1 · Кольцо фокуса не видно на тёмном фоне

Токен был заливкой с прозрачностью 12%. Заменён на двухслойное кольцо; для контейнеров с `overflow: hidden` — врезанный вариант. Прошло по всему киту, а не по трём компонентам, как было сначала.

### ✅ P2 · Бургер-меню показывалось на десктопе

Одинаковая специфичность у класса шапки и класса кита; побеждал файл, подключённый позже (ADR-038).

### ✅ P2 · Телефон-заглушка занимал четверть шапки

В макете телефона в шапке нет; оставлен там, где навигация уезжает в меню.

### ✅ P2 · Ступенька фона над шапкой

Первый экран уведён под шапку отрицательным отступом.

### ✅ P2 · Первый экран не давал увидеть полосу доверия

874 → 792px: полоса видна на 68px без прокрутки при экране 860.

### ✅ P2 · Форма заявки растягивалась во всю ширину

Секция была без контейнера; заменена на двухколоночную из макета.

### ✅ P2 · Вертикальный ритм секций вдвое разрежённее макета

Разбор спецификации терял третье значение отступа (ADR-037).

### ✅ P2 · У последней секции не было отступа снизу

Задано структурно: `main > :last-child`.

### ✅ P3 · Блок «как обманывают» дублировал разбор сметы

Убран с главной, остаётся на странице установки.

### ✅ P3 · Плашка «характеристики из админки»

Внутренняя кухня, посетителю не нужна.

### ✅ P3 · Формулировки про «мастера за три тысячи»

Смысл сохранён, насмешка убрана.

### ✅ P3 · Заголовок первого экрана

Тире убрано, строки разделены явно, «за один день» связано неразрывными пробелами.

### 🔴 P1 · Страницы кластера повторяют блоки главной

Каталог, цены, монтаж, сервис и отзывы существуют и как секции главной,
и как отдельные страницы, причём с тем же текстом. Это хуже, чем одна
страница: две копии одного текста делят между собой вес и конкурируют в
выдаче за один запрос. Отдельный адрес окупается только уникальным
содержимым.

Что сделать: главная оставляет короткий тизер и ссылку, страница кластера
получает своё — полный прайс, полный список работ, свои примеры, свой FAQ.
Разбор решения — ADR-046.

### 🟡 P2 · Полоса доверия переносит содержимое на вторую строку

На средней ширине четыре пункта не помещаются в ряд и четвёртый уезжает
вниз, ломая высоту первого экрана. Нужна не перестройка в столбец, а
горизонтальная прокрутка ряда — с автопрокруткой, останавливающейся при
наведении и при `prefers-reduced-motion`. Файл:
`apps/web/src/widgets/trust/TrustStrip.module.css`.

### 🟡 P2 · Сетка каталога оставляет висящий ряд

Карточки разложены жёсткой сеткой, и при четырёх моделях на трёх колонках
четвёртая стоит одна в ряду — сетка выглядит незаконченной, и так на любом
числе моделей, не кратном числу колонок. Количество моделей задаётся в
админке, поэтому подобрать «удобное» число нельзя.

Что сделать: раскладка не должна зависеть от остатка от деления —
горизонтальная лента с прокруткой (карусель со snap) либо сетка, честно
заполняющая последний ряд. Плюс: карточка сейчас отдаёт больше половины
высоты заглушке фото. Файл:
`apps/web/src/widgets/catalog/Catalog.module.css`.

### 🟡 P2 · Ряд симптомов переносится вместо прокрутки

Шесть кнопок симптомов уже на широком экране занимают две строки, а на
телефоне встанут в четыре — блок диагностики разъезжается по высоте, и
выбранный симптом уезжает от результата. Нужна та же горизонтальная лента с
прокруткой, что и для полосы доверия: ряд остаётся одной строкой на любой
ширине. Файл: `apps/web/src/widgets/service/Diagnostics.module.css`.

### 🔴 P1 · Ритм отступов между блоками всё ещё рваный

Правило «отступ только сверху» (ADR-037) приведено к единому виду в файлах
блоков, но на странице разница между секциями по-прежнему видна. Причины,
которые нужно проверить по очереди:

1. Секции с собственным фоном (`--bg-soft`, `--lead-grad`) держат отступ и
   снизу — это осознанно, но рядом с соседом на общем фоне суммарный зазор
   получается двойным.
2. Внутри блоков заголовок и содержимое добавляют свои `margin`, и они не
   выровнены между блоками.

Мерить по факту в браузере (`getBoundingClientRect`), а не по CSS: значения
`clamp` на разных ширинах дают разный результат.

### 🟡 P2 · Запуск проекта без Docker не работает

`pnpm install` на хосте отдаёт пустой `node_modules` и 2481 ошибку типов —
клиент Prisma не сгенерирован. Нужен рабочий путь мимо Docker: он был
обещан, чтобы среда Claude не поднимала контейнеры.
