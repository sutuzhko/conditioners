# PRD: Доработки после аудита — безопасность и доступ

**Дата**: 2026-08-29
**Статус**: Draft

## Цель

Закрыть десять открытых дефектов доступа и защиты из [BUGS.md](BUGS.md), из
которых пять — P1: монтажник читает чужие персональные данные, вход в панель
уводит на чужой сайт, боевой вход не сработает на первом же деплое, дев-стенд
с настоящими данными владельца слушает сеть, а демо-сид способен стереть
боевую базу. Каждый из них — это либо утечка персональных данных (152-ФЗ),
либо неработающая выкладка, либо потеря данных владельца.

## Пользовательские сценарии

- Монтажник открывает календарь работ → видит только свои дела и не видит ни
  одной чужой заявки, ни телефонов чужих клиентов
- Владелец входит в панель по ссылке с параметром возврата → попадает только
  на адрес внутри своего сайта
- Владелец разворачивает прод по [DEPLOY.md](DEPLOY.md) → вход в панель
  работает с первого раза, хеш пароля доезжает до контейнера целиком
- Разработчик поднимает дев-стек на машине в сети → панель и база доступны
  только с этой машины
- Посторонний получает образ `worker` → в метаданных нет строки подключения с
  боевым паролем
- Чужой сайт пытается выкинуть владельца из панели или залогинить его в
  подставную учётную запись → запрос отклонён
- Посторонний со ссылкой на фото объекта клиента → не получает его без сессии
- Разработчик запускает `pnpm seed:demo` при боевой строке подключения →
  скрипт отказывается работать, а не стирает семнадцать таблиц
- Монтажник отправляет списание на пять тысяч строк → получает отказ по
  ограничению, база не встаёт

## В скоупе

- **P1 · Календарь отдаёт монтажнику все дела и все заявки месяца**
  ([BUGS §2833](BUGS.md)) — `listRange` и `listCreatedBetween` не принимают
  `Viewer`, страница зовёт их без фильтра. Имя, телефон, адрес и заметка по
  всем делам владельца уходят монтажнику
- **P1 · Открытый редирект после входа в панель** ([BUGS §2854](BUGS.md)) —
  проверка `next` ловит `//злодей.example`, но не `/\злодей.example`
- **P1 · `$` в `.env.prod` съедается compose** ([BUGS §2908](BUGS.md)) — хеш
  Argon2id и пароль SMTP приезжают в контейнер обрубком, `verify` всегда
  возвращает false
- **P1 · Дев-состав публикует панель и базу наружу** ([BUGS §2928](BUGS.md)) —
  `'3000:3000'` и `'5432:5432'` на `0.0.0.0`, учётка `admin`/`admin`, пароль
  базы `devpass`, а в базе — настоящие данные владельца
- **P1 · `seed:demo` стирает 17 таблиц, а предохранитель смотрит не на ту
  базу** ([BUGS §3596](BUGS.md)) — безусловный `deleteMany()`, проверка идёт
  по `NODE_ENV` и `SITE_URL`, а не по строке подключения
- **P2 · Боевой пароль базы запекается в конфигурацию образов**
  ([BUGS §2971](BUGS.md)) — `ENV DATABASE_URL` виден в `docker inspect`
  долгоживущего образа `worker`
- **P2 · Вход и выход не проверяют кросс-сайтовость**
  ([BUGS §2991](BUGS.md)) — `isCrossSiteMutation` стоит в `withAdmin` и
  `withOwner`, но не в `POST /api/auth/login` и `/api/auth/logout`
- **P2 · Фото объекта клиента отдаются без сессии** ([BUGS §3000](BUGS.md)) —
  публичный `/api/media/{name}` с годовым кешем, тогда как документы того же
  наряда закрыты сессией и в комментарии названы персональными данными
- **P2 · Списание в наряд не ограничено по числу строк**
  ([BUGS §3704](BUGS.md)) — `orderConsumeSchema.lines` без `.max()`
- **P3 · Сервер: мелочи контракта и защиты — пачка**
  ([BUGS §3468](BUGS.md)) — принадлежность заметки сотруднику не сверяется при
  удалении, `/api/prices` отдаёт строки Prisma со служебными полями, остальные
  пункты пачки

## Не в скоупе

- Отдельная база для сквозных тестов — она же разблокирует e2e в CI, но это
  инфраструктурная задача:
  [prd-infrastructure-quality.md](prd-infrastructure-quality.md)
- Затирание правок коллеги при параллельной работе и реалтайм — это
  конкурентность и контракт, а не доступ:
  [prd-data-performance.md](prd-data-performance.md)
- Ротация скомпрометированного токена бота, покупка домена, настройка VPS —
  шаги владельца, разработкой не закрываются
- Аудит зависимостей и внешний пентест — не заявлялись

## Технические ограничения

- **Персональные данные хранятся в РФ и не покидают сервер** (инвариант 12,
  152-ФЗ). Любое послабление доступа к фото и документам недопустимо
- **Роли уже описаны таблицей маршрутов** (ADR-149) — новый доступ добавляется
  туда, а не проверкой на месте
- **Ограничение доступа не должно ломать инвариант 2**: заявка сначала
  пишется в БД, ответ `201` не зависит от внешних сервисов
- **Правка `docker-compose.dev.yml` меняет среду разработки** — дев тоже в
  Docker (ADR-017), и после смены адресов публикации порты придётся
  переоткрыть всем, кто ходит на стенд с другой машины; решение фиксируется
  ADR
- **Закрытие `/api/media` сессией задевает публичные изображения**: обложки
  статей и фото товаров обязаны остаться публичными и кешируемыми, иначе
  страдает LCP (инвариант 13, бюджеты производительности)
- **Проверка `$` в `.env.prod` проверяется только выкладкой** — локальный
  прогон полного прод-компоуза обязателен до первого деплоя
- **Тест на каждый P1 пишется до правки** (TDD обязателен там, где ошибка
  стоит денег: доступ по ролям, запись заявки)

## Критерии готовности

- [ ] Сквозной тест: монтажник открывает календарь и не получает ни одной
      чужой записи и ни одной заявки — проверка ответом API, а не экраном
- [ ] Интеграционный тест: `next=/\evil.example`, `next=//evil.example`,
      `next=https://evil.example` после входа ведут на `/admin`
- [ ] Хеш Argon2id со всеми `$` доезжает до контейнера целиком — проверено
      локальным прогоном `docker-compose.prod.yml` со входом в панель
- [ ] `docker compose -f docker-compose.dev.yml config` показывает публикацию
      портов только на `127.0.0.1`
- [ ] `docker inspect` образов `build` и `worker` не содержит строки
      подключения с паролем
- [ ] Интеграционный тест: `POST /api/auth/login` и `/api/auth/logout` с
      чужим `Origin` отклоняются
- [ ] Фото объекта клиента отдаются только с сессией; публичные изображения
      каталога и статей остаются публичными и кешируемыми — проверено тестом
      на оба случая
- [ ] `pnpm seed:demo` отказывается работать, когда строка подключения не
      указывает на дев-базу; отказ покрыт тестом
- [ ] `POST /api/admin/orders/{id}/consumption` с числом строк выше предела
      отвечает 400 с внятным сообщением
- [ ] `pnpm check` в контейнере зелёный до и после каждой фазы
- [ ] Каждый пункт отмечен закрытым в [BUGS.md](BUGS.md) тем же коммитом,
      решения по способам защиты записаны в [DECISIONS.md](DECISIONS.md)
