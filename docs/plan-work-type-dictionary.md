# Plan: Единый справочник видов работ

**PRD:** [docs/prd-work-type-dictionary.md](prd-work-type-dictionary.md)
**Решение:** [ADR-343](DECISIONS.md)
**Дата:** 2026-09-08

## Фазы реализации

### Фаза 1: Справочник существует, календарь берёт краску из него

**Цель:** Сквозной минимум — вид работ живёт в базе, и это видно на экране.
**Затрагивает:** database / backend / frontend
**Задачи:**

- [ ] Миграция: справочник видов работ — код, название, цвет, значок, порядок,
      признаки «предлагать на сайте» и «активен»
- [ ] Сид заполняет справочник нынешними значениями `KIND_LOOK` и `ORDER_LOOK`
- [ ] Запись календаря ссылается на справочник; метка берёт краску оттуда
- [ ] Перечень `KIND_LOOK` снимается с кода
- [ ] Тесты: метка календаря красится значением из базы; правка цвета в базе
      меняет метку

**Когда готова:** цвет вида работ меняется правкой в базе и виден в сетке
календаря; перечня в коде не осталось.

### Фаза 2: Наряды переезжают на справочник

**Цель:** Тип наряда и вид дела — одно понятие.
**Затрагивает:** database / backend
**Задачи:**

- [ ] Миграция: наряд ссылается на справочник, `OrderType` снимается с
      приведением данных
- [ ] Перечень `ORDER_LOOK` снимается с кода
- [ ] Удаление вида работ, на который ссылаются записи, запрещено — только
      отключение
- [ ] Тесты: старые наряды открываются с прежним видом работ; удаление занятого
      вида отклоняется

**Когда готова:** ни одного перечня видов работ в коде; наряды сохранили тип.

### Фаза 3: Заявка получает вид работ

**Цель:** Ярлык темы в очереди окрашен по виду работ, а не серым.
**Затрагивает:** database / backend / frontend
**Задачи:**

- [ ] Миграция: заявка ссылается на вид работ; свободная тема остаётся полем
- [ ] Ярлык в очереди обращений берёт краску и подпись из справочника
- [ ] Рядом с цветом всегда слово: цвет не единственный признак
- [ ] Заявки без вида работ открываются и не роняют экран
- [ ] Тесты: ярлык окрашен значением справочника; старая заявка без вида
      открывается

**Когда готова:** «установка» в заявке и в календаре одного цвета, старые
заявки на месте.

### Фаза 4: Форма заявки на сайте

**Цель:** Посетитель выбирает вид работ, и это доезжает до панели.
**Затрагивает:** frontend / backend
**Задачи:**

- [ ] Список видов работ приезжает с сервера в разметке страницы (инвариант 1)
- [ ] Поле выбора в форме заявки рядом со свободной темой
- [ ] Валидация на сервере той же схемой: неизвестный вид не принимается
- [ ] Истории Storybook формы: выбран вид, не выбран, ошибка
- [ ] Тесты: сквозная отправка заявки с видом работ до записи в базе

**Когда готова:** заявка с сайта приходит с видом работ, разметка страницы
содержит список без участия клиентского кода.

### Фаза 5: Владелец правит справочник

**Цель:** Новый вид работ заводится без разработчика.
**Затрагивает:** frontend / backend
**Задачи:**

- [ ] Раздел справочника в настройках: заведение, правка, порядок, отключение
- [ ] Палитра ограничена красками, проходящими AA в обеих темах; контраст
      проверяется при сохранении
- [ ] Истории Storybook: список, заведение, отключённый вид, отказ по контрасту
- [ ] Просмотр по скиллу `ui-ux-pro-max` на 1440, 768, 390 в обеих темах
- [ ] Тест контраста: ни одна краска справочника не даёт ниже AA

**Когда готова:** владелец заводит «Чистку дренажа» с цветом и значком, и она
появляется в заявке, календаре и наряде.
