# PRD: Визуальная регрессия без хранения снимков в git

**Дата**: 2026-08-31
**Статус**: Draft

## Цель

Убрать 3408 PNG-эталонов (123,6 МБ, весь прирост `.git`) из публичного
репозитория вместе с ручным заданием их пересчёта, не потеряв ни одного из
трёх свойств визуальной регрессии: регрессия на экране, куда никто не смотрел,
красит PR; осознанное изменение внешнего вида видно в PR и принимается явно;
ничего из этого не зависит от платного сервиса. Заодно снять упор в дев-сервер
витрины, из-за которого снимки идут десять минут (ADR-230, ADR-231).

## Пользовательские сценарии

- Разработчик правит `Button.module.css` → PR показывает список историй, чьи
  кадры изменились, и картинки разницы; ставит ярлык `vr:accepted` → проверка
  зелёная, принятие записано в PR
- Разработчик правит документацию → проверки снимков зелёные за секунды, как и
  сейчас (ADR-221)
- Разработчик добавляет историю → она снимается и проверяется инвариантами, а
  сравнивать её пока не с чем — проверка не краснеет из-за отсутствия эталона
- Разработчик ломает раскладку на экране, которого не открывал (документ вбок,
  кнопка под липкой полосой, тап-зона 0×0, тёмная тема без тёмного фона) →
  инвариант называет историю, ширину, тему и элемент числом — без эталона и
  без картинки
- Разработчик меняет радиус карточки → текстовый дифф измерений в PR показывает
  ровно задетые истории и ровно это свойство; оборачивает блок в лишний
  `<div>` → дифф пуст
- Владелец клонирует репозиторий → в нём нет ни одного PNG-эталона, `.git` не
  растёт от регрессии
- Коммит попадает в `main` → его кадры записаны в кеш, следующий PR сравнивается
  с ними без пересъёмки базы
- Следующая сессия читает CLAUDE.md, ROADMAP и HANDOFF → там описан действующий
  порядок, а не задание «Эталоны снимков»

## В скоупе

Пиксели без хранения:

- Эталон кадра — кадр `merge-base`, снятый в той же работе тем же контейнером и
  раннером; кадры `main` — в кеше Actions по SHA и версии отрисовщика; при
  промахе база снимается в работе
- Сводка расхождений в работе (истории, ширины, темы) и картинки разницы
  артефактом; шлюз ярлыком `vr:accepted`; отказ сценария и падение раннера
  красят всегда
- Новые истории снимаются без сравнения
- Все PNG-эталоны удалены из репозитория, `*-snapshots` в `.gitignore`, задание
  «Эталоны снимков» снято, документация приведена к новому порядку

Время ожидания:

- Витрина под снимки собирается статикой и раздаётся образом `caddy`;
  равенство кадров со старыми эталонами доказано до их удаления
- Кадры делятся по шардам матрицей работ; имена обязательных проверок `vr` и
  `vr-panel` сохраняются

Инварианты без эталона — на всех историях, включая `Админка/`, на ширинах
раздела в обеих темах:

- горизонтальное переполнение документа; размер интерактивных целей (24×24, в
  сенсорных раскладках 44×44 — ADR-183); фон документа равен токену темы;
  обрезанный текст без многоточия; перекрытие цели другим элементом;
  загруженность шрифтов и изображений
- у каждого правила — история-фикстура с нарочным нарушением, на которой
  правило падает; существующие нарушения починены или допущены параметром
  истории с причиной

Измерения текстом:

- один текстовый файл на историю: геометрия по ширинам, палитра по темам, узлы
  по стабильным именам, координаты относительно записанного предка, текст с
  числом строк, шрифты; файлы лежат в git
- сравнение с допусками, отчёт текстом в сводке работы; обновление файлов — из
  артефакта работы одной командой либо локально, и локальное сходится с CI в
  пределах допуска

Диагностика покрытия:

- отчёт о побайтно одинаковых кадрах разных историй; найденные пары разобраны
- утверждение «контрольный элемент стоит на месте во всех состояниях» как
  параметр истории
- граф импортов (#444) применён к пиксельному слою

## Не в скоупе

- Внешние сервисы визуальной регрессии и любые платные подписки (ADR-230)
- Постоянное хранение пикселей где бы то ни было — LFS, Releases, S3, отдельный
  репозиторий
- Снимки разделов `Админка/` пикселями: они рисуются из базы и ждут фикстур
  (ADR-207); инварианты их покрывают уже сейчас
- Состояния наведения и фокуса, которых история не показывает сама
- Контраст текста на полупрозрачных подложках — его меряет
  `scripts/admin-contrast.mjs`, в инварианты он в этой итерации не переносится
- Изменение набора ширин и тем (ADR-207, ADR-221)

## Технические ограничения

- Кадры снимаются только в Linux-образе (эта часть ADR-168 остаётся): обе
  стороны сравнения обязаны быть сняты одним контейнером в одной работе
- Кеш Actions — 10 ГБ на репозиторий, записи без обращений неделю удаляются;
  кеш `main` виден всем PR, кеш PR — только ему самому. Промах кеша — штатный
  путь, а не ошибка
- Ярлык на PR сам проверок не перезапускает: работа обязана слушать события
  `labeled` / `unlabeled`
- Push из работы токеном `GITHUB_TOKEN` не запускает проверок на новом коммите
  — поэтому файлы измерений работа не коммитит в ветку сама, а отдаёт
  артефактом
- Новые зависимости — только с согласия владельца; статику раздаёт уже
  используемый образ `caddy`, раннер остаётся Playwright
- Машина разработчика полный состав Docker не тянет (ADR-173): всё, что требует
  Linux-кадров, проверяется в CI
- Имена обязательных проверок `check`, `e2e`, `vr`, `vr-panel` зашиты в защиту
  `main`

## Критерии готовности

- [ ] В репозитории нет ни одного PNG-эталона; `*-snapshots` в `.gitignore`;
      задания «Эталоны снимков» нет
- [ ] PR без визуальных правок: `vr` и `vr-panel` зелёные, кадры сравнены с
      кадрами `merge-base`
- [ ] PR с нарочным сдвигом в 1px: работа красная, сводка называет историю,
      ширину и тему, артефакт содержит разницу; с ярлыком `vr:accepted` —
      зелёная
- [ ] Новая история в PR не красит работу отсутствием эталона
- [ ] Отказ сценария истории красит работу и с ярлыком
- [ ] Push в `main` записывает кадры в кеш; следующий PR берёт их оттуда — в
      журнале работы виден `cache hit`
- [ ] Кадры статической витрины совпали с прежними эталонами до их удаления
      (разошедшихся 0, либо каждое разобрано в ADR-231)
- [ ] Критический путь снимков при попадании в кеш — не больше 5 минут; числа
      до/после записаны в ADR-231
- [ ] Инварианты идут на всех историях в обеих темах; каждое правило падает на
      своей фикстуре; допущения лежат в историях параметром с причиной
- [ ] Измерения: правка радиуса карточки даёт дифф ровно в задетых историях и
      ровно по этому свойству; лишняя обёртка `<div>` не меняет ни строки;
      локальный пересчёт на macOS сходится с CI в пределах допуска
- [ ] Отчёт о дублях кадров: пар «разные состояния — одинаковый кадр» нет, либо
      каждая разобрана
- [ ] CLAUDE.md, ROADMAP.md, HANDOFF.md и комментарии раннера описывают новый
      порядок; ADR-230 и ADR-231 записаны
