# Plan Generator

Прочитай план из файла: $ARGUMENTS

Для каждой фазы создай milestone и issues в GitHub, используя gh CLI.

## Порядок действий

1. Прочитай файл плана
2. Прочитай словарь ярлыков — `scripts/labels.mjs`. Ярлыки берутся **только
   оттуда**; выдуманного ярлыка не существует, `gh` заведёт его молча и
   разметка разъедется
3. Для каждой фазы создай milestone:
   `gh api repos/:owner/:repo/milestones -f title="Фаза N: название"`
4. Для каждой задачи в фазе создай Issue:
   `gh issue create --title "..." --body "..." --label "..." --milestone "..."`
5. Прогони ревизор: `node scripts/labels-audit.mjs` — он назовёт задачи с
   неполной разметкой

## Формат Issue

**Title**: текст задачи из плана (без [])
**Body**: описание задачи

## 🔴 Ярлыки — четыре оси

Границы между похожими ярлыками описаны в [docs/LABELS.md](../../../docs/LABELS.md).

| Ось         | Сколько на задаче | Значения                                                            |
| ----------- | ----------------- | ------------------------------------------------------------------- |
| `area/`    | 🔴 ровно одна     | `site` `panel` `api` `shared` `infra` `process` `docs`          |
| `module/`   | ноль или больше   | 20 разделов панели и сайта, см. словарь                              |
| `kind/`      | 🔴 ровно один     | `bug` `enhancement` `audit` `refactor` `verification` `decision`      |
| `quality/` | ноль или больше   | `a11y` `perf` `security` `seo` `responsive` `dark-theme` `privacy` |

Обязательные оси обязательны: задача без `area/` или без `kind/` получит
заметку ревизора на GitHub и всё равно вернётся к тебе.

Подсказки по выбору:

- задача-приёмка фазы («Проверка: …», «Снимки …», «Замеры …») — `kind/verification`
- найдено ревью или замером, снаружи ещё никого не задело — `kind/audit`
- правка в `shared/` — `area/shared`, даже если поводом был экран панели
- разделов может быть несколько: расход материалов в наряде — и `orders`, и
  `stock`
