# Plan Generator

Прочитай план из файла: $ARGUMENTS

Для каждой фазы создай milestone и issues в GitHub, используя gh CLI.

## Порядок действий

1. Прочитай файл плана
2. Прочитай словарь ярлыков — `scripts/labels.mjs`. Ярлыки берутся **только
   оттуда**; выдуманного ярлыка не существует, `gh` заведёт его молча и
   разметка разъедется
3. Для каждой фазы создай milestone:
   `gh api repos/:owner/:repo/milestones -f title="Фаза N: название"`
4. Для каждой задачи в фазе создай Issue:
   `gh issue create --title "..." --body "..." --label "..." --milestone "..."`
5. Прогони ревизор: `node scripts/labels-audit.mjs` — он назовёт задачи с
   неполной разметкой

## Формат Issue

**Title**: текст задачи из плана (без [])
**Body**: описание задачи

## 🔴 Ярлыки — четыре оси

Границы между похожими ярлыками описаны в [docs/LABELS.md](../../../docs/LABELS.md).

| Ось         | Сколько на задаче | Значения                                                            |
| ----------- | ----------------- | ------------------------------------------------------------------- |
| `часть/`    | 🔴 ровно одна     | `сайт` `панель` `api` `общее` `инфра` `процесс` `документы`          |
| `раздел/`   | ноль или больше   | 20 разделов панели и сайта, см. словарь                              |
| `тип/`      | 🔴 ровно один     | `дефект` `улучшение` `аудит` `рефакторинг` `проверка` `решение`      |
| `качество/` | ноль или больше   | `доступность` `производительность` `безопасность` `seo` `адаптив` `тёмная-тема` `пд` |

Обязательные оси обязательны: задача без `часть/` или без `тип/` получит
заметку ревизора на GitHub и всё равно вернётся к тебе.

Подсказки по выбору:

- задача-приёмка фазы («Проверка: …», «Снимки …», «Замеры …») — `тип/проверка`
- найдено ревью или замером, снаружи ещё никого не задело — `тип/аудит`
- правка в `shared/` — `часть/общее`, даже если поводом был экран панели
- разделов может быть несколько: расход материалов в наряде — и `наряды`, и
  `склад`
