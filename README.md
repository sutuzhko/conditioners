## Дизайн

🔴 **Дизайн-исходники в репозиторий не выкладываются** — каталог `design/` в `.gitignore`. Прототипы из Claude Design хранятся локально у разработчика (архив `Сайт кондиционеров Тула-handoff.zip`), в том числе потому, что внутри лежит скомпрометированный токен Telegram-бота.

Эталон визуала — прототипы `design/Кондиционеры Тула.dc.html`, `design/База знаний.dc.html`, `design/Админ-панель.dc.html`. Открываются в браузере как обычные HTML-файлы. Воспроизводятся визуально; внутреннее устройство прототипа (инлайн-стили, `support.js`) в продакшн не переносится.

Всё, что нужно для работы **без доступа к исходникам**, извлечено в документацию: токены и правила вёрстки — в [DESIGN_BRIEF](docs/DESIGN_BRIEF.md), контракт — в [API](docs/API.md), доменная логика и структуры данных — в [PROJECT](docs/PROJECT.md).

## Разработка

Кода пока нет — проект на этапе фундамента, см. [ROADMAP](docs/ROADMAP.md).

🔴 Разработка ведётся **только в Docker** — дев-окружение повторяет боевое, чтобы расхождения сред всплывали на первой итерации, а не при деплое ([ADR-017](docs/DECISIONS.md)). `npm run dev` на хосте не поддерживается.

```bash
cp .env.example .env.dev
docker compose -f docker-compose.dev.yml up --build
```

Команды — внутри контейнера:

```bash
docker compose -f docker-compose.dev.yml exec web npx prisma migrate dev
```

## Главное в четырёх строках

Публичные страницы отдаются сервером уже с данными — иначе поисковики не увидят каталог и цены.
Заявка сначала пишется в базу, и только потом уходит уведомление — иначе клиент теряется при первом сбое внешнего сервиса.
Ни одного факта о компании и ни одного товара в коде — всё правится владельцем из админки.
Каждое решение записывается в [DECISIONS.md](docs/DECISIONS.md) в день принятия.
